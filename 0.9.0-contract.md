# 0.9.0 — The host contract: the column engine, hosted

What a host page may do with this repository's column engine, and what it may not. Written
for the globe's adapter (`0.9.0-plan.md` §2 M3) and for any other page that wants a live
cross-section instead of a screenshot. The harness that keeps this document honest is
`experiments/namespace.js` §E; the page that consumes it is M2's `library.html`.

Status: **M1 landed** (2026-10-18) — every line below is true in code and measured by that
harness; the decisions §1–§2 record and the worklog is `archive/0.9.0-M1-contract-worklog.md`.

## 0. The shape

The engine is a set of classic scripts, one global each, loaded once by the host page:

- the 25 engine files: `COLP, COLS, COLCOLUMNS, COLSIM, COLGEO, COLRNG, COLSURF, COLPLATES,
  COLSLAB, COLMANTLE, COLMAGMA, COLERUPT, COLCRUST, COLORE, COLPERF, COLUI, COLRENDER,
  COLDEPOSITCORE, COLDEPOSITS, COLSEED, COLSECTION, COLCHECKPOINT, COLCOUPLING, COLLINK,
  COLCORELOG`;
- the two frozen data modules: `COLDEPOSITMODELS`, `COLDEPOSITECONOMICS`;
- the two shared formats, one load per host page: `SlicePack` (`port/slice-format.js`),
  `CoreLogFormat` (`port/core-log-format.js`);
- the bundle table: `SECTION_PACKS`, one object, the host's own data files may add to it.

The engine never starts itself and never reads the page it happens to live in. The host
starts it, and the host is the only thing the engine knows about the DOM.

## 1. The host

- **A host is a document or an element. A window is not a host.** The engine's controls are
  page-global ids and it paints into `#c` inside the host; a window is a realm, not a
  container, and a foreign page's own `#c` would answer to the same name.
  `COLSIM.start(window)` is refused by name: `COLSIM.start does not take a window: the host is
  a document or an element`.
- **The host is required.** `COLSIM.start()` with no host is refused by name:
  `COLSIM.start needs a DOM host and requestAnimationFrame`. There is no ambient page lookup
  — a page says what it is. `columns.html` says `COLSIM.start(document)`.
- **A refused start changes nothing**: the engine is not running, no control is bound, no host
  is kept, and a running engine is not stopped by a refused start.
- **The engine reads no page name off its own global.** `document`, `location`, the frame
  clock, the event bus and the storage are reached through the host and through the host's
  window, never off the engine's own global. (M0's `page()` probe — "am I in a page?" — read
  `root.document` on every stop; M1 removed it: the question "where are my globals?" is
  answered by the module system, not by the DOM.)
- A host that mounts **without** the chrome (`COLUI.build` skipped) is not supported: the HUD
  and the sliders are the section's own controls. A host that wants them hidden wraps the
  container in CSS; it does not fork the engine.

## 2. The entries

Every entry below is a name the adapter may call. `experiments/namespace.js` §E reads this
list and checks each entry against the loaded engine, so the contract cannot name a thing the
code does not have — and a name that moves is a red until this list moves with it.

```
COLUI.build(host)            function
COLSIM.start(host)           function
COLSIM.stop()                function
COLCOUPLING.apply(msg)       function
COLCOUPLING.last             receipt
COLCORELOG.build(state, o)   function
COLCORELOG.json(msg)         function
COLCORELOG.note()            function
COLSECTION.mode              state
COLSECTION.syncLive          state
COLSECTION.syncStale         state
COLSECTION.syncPaused        state
```

## 3. Mount

- `COLUI.build(hostElement)` writes the engine's control subtree into the container the host
  provides: the bar (the two clock sliders, the four camera presets, the mesh and deposit
  switches, the seed field, the session save/load), the stage (the canvas `#c`, the HUD, the
  two axis scale sliders), the ore panel and the help line. The id set is the contract:
  `columns.html` keeps the static spelling of the same chrome, and the harness pins the
  built set to the page's set, so a control cannot exist in one spelling and not the other.
- `COLUI.build` refuses a host that is not an element, and a host that already carries the
  chrome: `COLUI.build needs a host element`, `COLUI.build: the host already carries the
  chrome`.
- The chrome is semantic, not styled: ids, roles, `aria-pressed`, titles and placeholders
  are the engine's; the stylesheet is the host's. `columns.html` carries it in a `<style>`
  block, and a host that wants the section to look like our page copies that block or writes
  its own rules for the ids in §2's list.
- The canvas the engine paints is `#c` inside the host. `COLSIM.start(hostElement)` finds it
  through the host (`getElementById` for a document, `querySelector` for an element), so a
  nested container works.

## 4. Start and stop

- `COLSIM.start(host)` starts one frame loop and binds the chrome's controls. A second
  `start` with the same host is the same loop: nothing re-bound, nothing reset. `start` with
  a different host stops the first.
- `COLSIM.stop()` cancels the pending frame, releases every listener it bound and keeps the
  host. A frame already in flight when `stop()` ran does nothing. A second `stop()` is a
  no-op, and a `start` after a `stop` is a clean restart that replays the first start bit for
  bit.

## 5. Coupling in

- One call per message: `COLCOUPLING.apply(msg)`. The message is the `pgt-coupling` v1
  envelope the globe's own writer produces; a message for another path is refused and the
  section is left untouched (`experiments/coupling.js` §C2 owns that gate).
- `COLCOUPLING.last` is the receipt: `matched`, `fresh`, `retired`, `reconciled`, `diverged`,
  `identityError` and the plate-membership counts, after every apply.
- The section does not drive the globe. A coupling message supplies plate kinematics; the
  section's own K2 runs when no live message has.

## 6. Observations out

- `COLCORELOG.build(state, opts)` selects the columns worth logging at the cadence;
  `COLCORELOG.json(msg)` is the wire text; `COLCORELOG.note()` commits the log after the host
  has accepted it. The commit-on-acceptance rule is §8.5's and is unchanged: a failed send
  stays due.
- An observation is a report. The globe may display it; it may not ingest it into a kernel.

## 7. Mode and staleness

- The section says which mode it is in through its own banner fields: `COLSECTION.mode`
  (the page is showing a cut), `COLSECTION.syncLive` (a live rung answered),
  `COLSECTION.syncStale` (a live rung went quiet and the section demoted itself to its own
  solve) and `COLSECTION.syncPaused` (the globe's clock is paused). There is no new
  mechanism: the demotion is §8.1's waiting-frame rule.
- A paused globe pauses the section's clock label by not calling: the section's rate is its
  own, and a paused globe sends a clock message with `paused` set.

## 8. What the host must not do

- Read engine internals outside the entries in §2. The engine's globals are the contract's
  surface, not its interior.
- Ingest an observation into its own kernels (boundary 3). The observation is the section's
  report about itself.
- Vendor either engine. The host loads this repository's scripts and the shared `port/`
  files; it does not copy them into its tree and does not rename them.
- Load a shared `port/` file twice: `SlicePack` and `CoreLogFormat` are one load per page,
  and a second copy under a second name is a second format.

## 9. The recorded collision, and how it was resolved

M0 measured one collision between the two pages: `DepositEconomics`, our frozen v1 scenario
(`js/data/deposit-economics.js`) and the globe's v2 scenario under the same name, two
different files. M1 resolved it on this side: our two frozen deposit modules now answer to
`COLDEPOSITMODELS` and `COLDEPOSITECONOMICS`, values unchanged, and the globe keeps its
`DepositEconomics`. Both sides record the rename — this document and the globe's own
repository — and the harness's collision check is strict again: the two pages' global sets
meet in `SlicePack` and nothing else.
