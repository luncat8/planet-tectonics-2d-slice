# 0.3.0-P3 — Plan: conserved melt and eruption

This plan turns the particle engine's diagnostic pressure-release melt overlay into a material
pipeline: mantle rock partially melts, melt segregates, some crystallises underground, some
feeds an eruption, and erupted particles land and weld into the crust. It extends the particle
engine described in `0.3.0-plan.md`; it does not alter the column engine.

P3 does **not** claim to solve plate collision, subduction, deep recycling or sedimentary
landscape evolution. Those require P4's contact and transport work. P2's `zh` diffusion is a
profile-only relief proxy: it moves no particles and produces no sediment.

## 1. Contracts before equations

### 1.1 Units and inventories

- Position is km, geological time is Myr, particle velocity is km/Myr, and particle `m` is
  model mass per unit out-of-plane depth. In P1's uniform-density convention, `m` is
  proportional to parcel area; P3 must state and test any density conversion it introduces.
- `T` is the existing dimensionless temperature. P3 adds specific enthalpy `H`, whose sensible
  and latent components use one documented normalized unit. The phase law is a mapping between
  `(H, pressure/depth, composition)` and `(T, melt fraction)`; a phase change may repartition
  `H`, never create or destroy it.
- Composition fields are mass fractions. Splitting and merging use mass-weighted composition,
  and any water, felsic material or melt carried by a particle remains in the global inventory.
- Counters for gross melting, intrusion and eruption are **throughput** diagnostics. They are
  not additional inventory and must never be added to the current phase totals.

### 1.2 Mass and enthalpy ledgers

Every active parcel has exactly one transport phase. The P3 inventory is the sum of model mass
in mantle/grid-coupled particles, mobile melt, fixed-capacity reservoirs, airborne particles and
landed deposits. Transfers between those categories are internal. P3 has no material source or
sink. P4 must book deep recycling as a transfer into a persistent deep inventory; any true
open-system source or export needs a separate ledger entry.

The heat invariant is

```
H_total(t) - H_total(0) = Q_wall(t) + Q_external(t) - Q_export(t)
```

P3 has no external heat source or export, so the wall-flux ledger is the only net change.
`H_total` includes sensible and latent heat in every phase and reservoir. The marker/grid
coverage error remains a separate diagnostic; it must not be disguised as phase-change energy.

### 1.3 Particle pool and phase routing

Keep a fixed-capacity structure of arrays and a dense active prefix `0..S.n`. Add a stable
integer material id and a deterministic split/merge order. A removal may compact the final
active slot into the hole, but the moved parcel keeps its id and every field is moved together.
Hash the active state in slot order, including ids, mass, enthalpy, phase, composition and
`zh`; repeated same-seed runs must reproduce the same ordering and fingerprint.

The phase is a transport/material state, not a plate id:

| phase | grid transfer and conduction | geological advection | solid clustering | airborne clock |
|-------|------------------------------|----------------------|------------------|-----------------|
| mantle / grid-coupled | yes | flow map | eligible by strength | no |
| mobile melt | contributes to the documented grid thermodynamics until detached | buoyant melt rule | no | no |
| airborne | no | no | no | yes |
| landed deposit | re-enters the shallow material/grid path at the surface boundary | coupled after landing | eligible as it cools and welds | no |

The exact enum values are implementation details; these routing rules are not. In particular,
`G.reseed` may repair only genuine grid-coverage holes and may not borrow, compact or move
airborne mass. Cluster and crust diagnostics must exclude airborne material. A full pool must
stage melt in its reservoir or defer a split; it must never silently drop a parcel.

## 2. Geological and presentation clocks

Melt production, segregation, reservoirs, cooling, welding and total emitted mass advance on
the geological clock. The particle flight path advances on elapsed wall time only, using the
presentation scale in `0.3.0-plan.md` §2.4. A clock slider change must not speed up or slow down
an already airborne clast. The page loop must pass a bounded wall-time interval to the flight
kernel; a paused geological clock may still finish a flight. A long suspended tab interval must
not teleport particles through the surface.

Every kernel is deterministic for a fixed seed, geological step sequence and wall-time
sequence. Zero geological time does not melt, cool, weld, move a reservoir or change a ledger;
only the explicitly wall-clock flight kernel may move airborne parcels.

## 3. Kernel order

P3 changes the order inside G4 so phase equilibrium can weaken rock before the same substep's
strength and cluster update:

1. **G1:** deposit only grid-coupled particles; record the same adjoint coverage weights used by
   the conduction gather. Add enthalpy/composition/melt fields only with independent transfer
   and ledger fixtures.
2. **G2:** solve convection from the thermal field. Add composition and melt buoyancy only
   after a manufactured sign/scale fixture and a coupled performance measurement.
3. **G3:** conduct, add the gathered heat increment to particle enthalpy, then advect
   grid-coupled parcels using the current equilibrium temperature.
4. **G4:** phase equilibrium, melt weakening, then the existing crust damage/cluster/rigid pass.
   Keep the one-way solid/fluid coupling unless a separate operator-consistent benchmark
   justifies changing it.
5. **G5:** detach mobile melt, manage reservoirs and intrusions, and enforce pool-cap policy.
6. **G6:** open conduits, schedule eruptions, advance airborne parcels on wall time, land them,
   and merge only after an explicit conservation check.
7. **G7/G8:** update the relief/profile view and report phase, mass, enthalpy, coverage and
   timing ledgers. Do not count `zh` diffusion as sediment transfer.

## 4. Milestones and evidence

### P3.0 — Pool and ledger foundation

Add the phase/id/enthalpy/composition storage, fixed-capacity transaction helpers, phase-aware
iteration rules and complete state fingerprint. Preserve the P2 page behavior: all initial
markers remain mantle, no physical melt is produced, and the diagnostic overlay is still
labelled as such.

Fixtures:

- `experiments/pt-p3-pool.js`: split, compact, merge and capacity-pressure operations preserve
  mass, momentum, enthalpy and composition; ids remain unique and deterministic;
- `experiments/pt-p3-routing.js`: airborne/deposit phases are excluded from mantle repair,
  conduction and clustering as specified, while grid-coupled coverage stays within the
  existing P1 ledger tolerance;
- `experiments/pt-p3-budget.js`: reports typed-array capacity, active count and full-frame cost
  at every quality level before the default reserve is chosen.

No numerical capacity is frozen in advance. The benchmark output sets it. Gate: no allocation
in frame kernels, no dropped material at capacity, and the existing P2 regression suite remains
green.

### P3.1 — Enthalpy and partial-melt equilibrium

Replace the visual-only melt potential with a per-material equilibrium state. Define and test a
solidus/liquidus relation over depth and composition, plus the normalized latent-heat law. Calibrate
every tunable with `experiments/pt-p3-enthalpy.js`; do not reuse the pressure-release overlay's
source constants as physical melt parameters.

G3 must hand heat increments to `H`, not directly overwrite equilibrium `T`. The phase kernel
then maps enthalpy back to temperature and melt fraction. Test heating through melt onset,
partial melt, full melt, cooling/freezing, and repeated cycles in a closed parcel. With flow and
conduction disabled, equilibrium mapping cannot change a parcel's `H`; in a closed no-wall-flux
grid, conduction may redistribute parcel enthalpy but cannot change the global sum. Each phase
transition conserves parcel `H` and `m`. This milestone may keep melt attached to its host; it
does not claim segregation or eruption.

### P3.2 — Melt segregation and intrusive storage

Split a melt-bearing parcel only when the capacity benchmark shows headroom. The host retains
its unmelted mass; the new melt parcel receives exactly the removed mass, enthalpy and
composition. Apply buoyant rise with a geological-time step. Add fixed-capacity chamber/reservoir
records and intrusion as transfers, not sinks. If a split cannot be admitted, leave the phase
fraction in its source parcel or stage it in the reservoir without losing mass.

`experiments/pt-p3-melt.js` gates rising hot melt, non-rising cold material, periodic wrapping,
coverage, and equality of total mass/enthalpy before and after segregation. A full coupled run
must report the marker/grid heat gap separately from the global enthalpy residual.

### P3.3 — Conduits, vents and eruption scheduling

A conduit opens from an overpressure rule checked against lithostatic load and local tensile
strength. Use the existing bond-damage machinery only after pressure units, signs and thresholds
have an independent fixture. A chamber's melt mass is transferred into a vent schedule; the
schedule may meter delivery but may not manufacture it. Full vent/pool capacity defers or stores
material instead of dropping it.

`experiments/pt-p3-erupt.js` gates closed/blocked conduits, effusive and explosive schedules,
reservoir-to-vent transfers, intrusive remainder, and exact inventory closure. Give each transfer
matching source/debit and destination/credit counters. Report gross melt-generation and route
throughputs separately from current stocks; never add throughput to phase or reservoir inventory.
Crystallized intrusions remain in the grid-coupled particle inventory exactly once.

### P3.4 — Flight, landing and welding

Airborne particles are ballistic presentation objects backed by actual melt mass. The flight
kernel integrates wall time; eruptive supply and the mass transferred to flight use geological
time. On landing, a clast returns to the material pool at the terrain horizon, cools, and becomes
eligible for bonds with age zero. The deposit must be part of a plate after `tauWeld`; no second
edifice copy may be kept in a renderer-only buffer.

Merging is permitted only for compatible phase and composition. Sum mass, momentum and
enthalpy; mass-weight composition and position; retain a deterministic surviving id. The test
covers both merge and inverse split to a relative error no greater than `1e-9` for mass,
momentum and enthalpy.

### P3.5 — Integrated acceptance and tuning

`experiments/pt-p3-check.js` runs the actual G1-G8 sequence at the demonstration clock and a
range of slider settings. Gate all of the following:

1. Global mass closes across every particle phase and reservoir to a relative error of at most
   `1e-9` using compensated summation; each split, merge and capacity transition is separately
   checked to `1e-9`, and no cap event loses material.
2. Global enthalpy changes only by the recorded wall flux, within the measured marker/grid
   coverage tolerance; latent heat is included.
3. Every melt transfer has matched source/debit and destination/credit counters. Current mass
   closure sums each particle or reservoir exactly once; gross melting, intrusion and eruption
   throughput is reported separately and is never added to those stock inventories.
4. A landed edifice joins the crust's cluster after `tauWeld`; a fountain remains legible for
   2-4 s regardless of the geological slider, and each clast follows the flight duration in
   §2.4.
5. Split/merge conservation reaches `1e-9`; the same seed, geological-step sequence and
   wall-time sequence give an identical complete-state fingerprint over 1000 frames.
6. `pt-check.js`, `pt-crust.js`, `pt-drift.js`, `pt-surface.js`, `pt-wrap.js` and `pt-ui.js`
   remain green, and `pt-p3-budget.js` confirms the measured default frame budget with melt and
   airborne populations present.

## 5. Decisions that experiments must settle

- The normalized solidus/liquidus curves, latent heat, composition/water influence and density
  contrast. These do not exist in the P1/P2 material model.
- The melt split criterion, pool reserve, chamber capacity and merge tolerance/radius.
- Whether particle buoyancy is adequately coupled through a deposited density field or needs a
  more expensive solid/fluid solve. Start with the measured one-way solver and only pay for a
  new coupling after a fixture demonstrates a physical gain.
- The wall-time clamp for a suspended page and the visual particle size required to resolve an
  edifice at the lid preset. Both must be calibrated by experiments before they become defaults.

P4 begins only after this ledger closes. It adds inter-plate contact/underthrusting, slab
recycling, arc melt and actual particle-based surface erosion/sedimentation; the P2 `zh` profile
diffusion remains a smoothing proxy, not a substitute for those transfers.

## 6. Interfaces this plan must keep

Four boundaries P3 must not cross, because the pages after 0.3 depend on them:

- **One global per new file.** A classic script's top-level `var` is a global, so the two
  engines overwrite each other's `P`, `S`, `SIM` the moment both are loaded into one page
  (`0.4.0-sync-plan.md` §4.7). Every file P3 *adds* is an IIFE that creates exactly one global —
  the one it exports. Existing files are not rewritten here; wrapping them is a prerequisite of
  a one-page 0.9, not of P3. A top-level `var P` or `var S` in a new file would make that pass
  larger for no reason.
- **`index.html` / `particles.html` are a fixture contract.** `experiments/pt-ui.js` parses the
  page and drives its ids, and it asserts the two files stay byte-identical. P3's UI additions
  (the phase inventory line, the eruption readout, any new switch) reuse the existing ids or
  land with the page and the fixture in one change.
- **The state is capturable.** Phase, stable id, enthalpy, composition and melt are part of the
  state, so they are part of the fingerprint (§1.3) and of the save format's field table
  (`0.4.0-sync-plan.md` E3). The version word is the only compatibility contract. The particle
  capacity is a parameter: a save records it and a load refuses a different one rather than
  reinterpreting a pool.
- **The eruption's presentation constants are settings.** The fountain's visual size, the flight
  duration scale and the wall-time clamp are tunables like any other; a capture records them, so
  a recorded eruption can be repeated frame for frame.
