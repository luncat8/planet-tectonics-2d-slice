# 0.4.2 — Plan: the `pgt-slice-pack` v2 cutover (slice side of globe 0.8.0–0.8.2)

This is the slice-side plan for the task handed over in the globe's
`https://github.com/luncat8/planet-geotectonics/0.8.0-slice-agent-prompt.md`. It executes, on this repository, what `0.4.0-sync-plan.md`
§2.8/§4.1/M4 and `0.4.1-plan.md` promised, superseded where the globe's 0.8 series has since
moved the contract: a **coordinated `pgt-slice-pack` v2 cutover, no legacy reader, no live
link**. The globe-side authorities are `planet-geotectonics`:

- `0.8.0-plan-slice-exchange-foundation.md` — the shared contract (§6 is the slice-side work
  list), provenance and compatibility gate;
- `0.8.1-plan-slice-cutter.md` — the globe's cutter and manual export (writer side, not ours);
- `0.8.2-plan-slice-bake.md` — deterministic Earth bakes via the globe's Node CLI (writer side);
- `0.8.3-plan-slice-bridge.md` — return observations and the deferred live bridge (gated, §C
  here, **not** started by this plan);
- `0.8.0-slice-agent-prompt.md` — the standing handoff brief this plan answers.

Local authorities that remain in force: `0.4.0-sync-plan.md` §1 (one owner per concept, four
kinds of exchange, port bumps), §1.8 (runtime authority), §4.7 (one page, one engine; the
`file://` ladder), `0.9.0-draft-sync.md` (the integrated globe is later and is **not** this).

## 1. Standing boundaries (inherited, not re-decided here)

1. **One owner per concept** (`0.4.0` §1.1, upstream 0.8.0 §3): globe owns geometry, the cell
   walk, plate motion, crust aggregates, sea level, ore potentials; the shared `port/` file
   owns pack schema/validation/quantisation/identities; this repo owns vertical beds, the
   section renderer, the section-local thermal model and section-local deposits. A returned
   core log is produced here and only *displayed* by the globe as `observed (section)`.
2. **A pack is a snapshot, not an authority handoff.** First product stays one-way:
   globe Copy/Saves a v2 file → this side loads and reconstructs. Contract transports are
   clipboard text and a downloaded `.json`; `postMessage`/`localStorage` are later
   conveniences on the §4.7 ladder, never replacements.
3. **No live coupling is started by this plan** — no `pgt-coupling` work, no core-log import
   into the globe, no two-way-validation claim — until the globe's 0.8.3 hard gates close
   (§C). The private coupling path hash is replaced by `SlicePack.pathChecksum` only when
   coupling is next planned, not before (upstream 0.8.0 §6.4).
4. **No deposit-catalogue backport in either direction.** `port/deposit-models.js` and
   `port/deposit-economics.js` are **not** updated to imitate the globe's 13-row catalogue;
   the six pack potentials (`oVms oMaf oArc oOro oBas oPla`) are the cross-project geology
   contract (upstream 0.8.0 §6.5). See decision D2 for what then happens to their manifest
   status.
5. **No v2 schema decision is made locally.** A schema proposal goes back through the globe's
   0.8.0 §5 procedure as a coordinated port bump. No legacy reader: v1 is rejected with a
   clear version error (upstream 0.8.0 §1, §4.3).
6. **Repo rules throughout** (`AGENTS.md`): `file://`-friendly classic scripts, guarded
   `module.exports`, tab indentation, LF, no hot-loop allocations, measured gates, worklog +
   report in `archive/` per milestone.

## 5. Phase C — gated, not started (recorded so nobody starts it by accident)

From upstream 0.8.3. This plan's only Phase-C deliverable is keeping the gates visible in
`roadmap.md`; implementation needs its own plan and the globe's explicit agreement.

- **C-return (0.8.3 §2):** a narrow `pgt-core-log` v2 observation protocol — valid logs import
  atomically, display-only in a side table labelled `observed (section)`, never mutate globe
  state/GPU/prospect ledger, and go *stale* (not silently current) when path, source checksum
  or globe state changes. Local prerequisite already exists in shape (`js/core-log.js`); the
  protocol work (identity binding to the exact received pack: full + path checksum) is not
  done and is not scheduled here.
- **C-live (0.8.3 §3):** the C0–C4 link state machine over a verified v2 payload; manual
  file/clipboard transport remains the escape hatch; no localhost/hidden service. **Hard gates
  before any C3/C4 work:** (1) repeated manual v2 round trips for CPU *and* GPU globe
  snapshots; (2) both sides reject identity/schema mismatches without partial mutation;
  (3) staleness correct after either world changes; (4) **this side automatically rebuilds
  section plate topology after incoming crossings — currently open, and it is a block, not a
  test gap**; (5) R4 evidence re-derivable (satisfied: 0.1.8/0.1.9); (6) fixed-seed,
  fixed-cadence runs prove no mass/clock/ownership ambiguity at handoff; (7) an explicit
  review decides whether C4 stays comparison-only.
- **0.9** (`0.9.0-draft-sync.md`) remains downstream of all of the above plus C1 namespacing
  (`0.4.1-plan.md` §8.6). Nothing in 0.4.2 is a step toward hosting; it only makes the file
  the hosting would carry trustworthy.

## 8. Risks and early warnings

| risk | warning sign | counter |
| --- | --- | --- |
| executing against a stale handoff (the prompt itself arrived stale) | fetched `port/` sha256 ≠ the manifest's, or fixture identities ≠ §4's values | D1: stop, re-read the handoff; hashes are the authority |
| silent drift masquerading as compatibility | a v1 bundle or fixture survives the cutover "because it still loads" | B3/B4 gates: no v1 artifact ships; v1 is refused by version, tested |

## 10. Cadence

One port bump = the Phase-B commit series and nothing else touching `port/`. Afterwards the
`0.4.0` §8 rules resume: sync audit at each counterpart release (re-read the divergence table,
re-run the shared fixture, record in `archive/`), and every future plan that touches a shared
concept names the counterpart commit it was written against — including re-verifying §0's
table, which is expected to be stale by the time anyone executes this.
