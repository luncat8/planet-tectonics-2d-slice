# 0.4.4 — Plan: the C-return/C-live agreement (re-opening Phase C by decision, not by code)

The scheduling decision both 2026-10-16 holds named as their re-open trigger. This plan
proposes to schedule the C-return import — the section's core log, read back by the globe as a
side table — exactly as the globe's `0.8.3-plan-slice-bridge.md` §2 specified it, and to close
the remaining C-live pair gates (1, 2, 3, 6) and the gate-7 review that sit on the same ladder.
It is written against the globe's then-current commit:

```
globe pin   3c960e7d924a6ca61b9609bd3c865988ce522ddd   (main tip, 2026-10-16, read fresh 2026-10-18)
slice base  47ec7b3  (0.4.3)
authority   0.4.1-plan.md §8.2/§8.5, 0.4.0-sync-plan.md §1.8/§4.7, globe 0.8.3-plan §2/§3
decision    accepted 2026-10-18: globe 0.8.4 (§2 of 0.8.4-answer.md) answers P1–P7 with
            "accept", P4 an explicit yes to positional beds; both §4 records exist, so M1 opened
```

Everything in §2 is a **proposal** the globe answers. Nothing in this plan touches `port/`,
`js/core-log.js`, `js/coupling*.js`, or any kernel; the implementation milestones (§5) start
only after both decisions exist (§4). Until then this plan changes no shared file and no
harness, and both 2026-10-16 dispositions stand.

  it is a **schedule both sides have recorded**.

## 4. The decision procedure (the negotiation itself)

1. This repository records the slice-side decision: 0.4.4 is scheduled — this plan, its return
   package (`archive/0.4.4-agreement-worklog.md` §5), and this document's status line. That
   satisfies this side's re-open clause.
2. The globe records its mirrored decision in a successor to its 0.8.3 disposition: which
   proposals (P1–P7) it accepts, which it answers differently, and when its §2.2 importer is
   scheduled against its own ladder (its 0.9.0 climate line may fairly go first).
3. Both recorded → implementation opens (§5). Either side missing → both holds resume, and the
   next input is the other side's answer, not more work here.
4. At implementation time the pin is re-checked: if the globe's tip has moved past `3c960e7`,
   this plan is re-read against that tip and the delta is recorded in the worklog before any
   shared byte moves (`experiments/upstream-drift.js` is the instrument; the 0.4.2 response §1.2
   is the precedent).

## 5. Milestones (each gated; none starts before §4.3)

### M0 — this plan and the return package
This document; the worklog with the proposal summary, the pins, and the decision text requested
of the globe; roadmap and AGENTS updated. Gate: the plan contains no implementation and touches
no shared file; `experiments/port-check.js` and `experiments/smoke.js` still pass untouched.

### M1 — the protocol text and fixture (after both decisions)
`port/core-log-format.js` v2 written once, byte-identical in both trees through the bump
procedure (0.8.0 §5): canonical body, codec-owned FNV/quantisation/key order, the §2 P3–P5 law,
`validate` returning `''` or a named reason, `parse` refusing on the checksum, `encode` the one
spelling. Fixture `port/fixtures/core-log-v2.json`: one valid log whose path identity is the
existing pack fixture's path and whose `packChecksum` is that fixture's full checksum — so the
two fixtures lock together and a corrupt-variant corpus is generated from them by each side's
own tests. `PORT.json` gains the two files and the two pin/note repairs (P2). Gate: each side's
independent test reads the fixture, round-trips it, and refuses a generated corpus of the
P5 classes; `port-check.js` extended to assert the new hashes on both sides' shape.

### M2 — slice-side adoption
`js/core-log.js` keeps build/select/commit (the cadence, the threshold, the sent-ledger) and
moves its codec half — body, checksum, quantisation, validation — to the port module, so the
section's build and the globe's filing run one law. `experiments/core-log.js` gains the port
module's own section (fixture round trip, corpus refusals) and re-runs its existing sections
unchanged. Gate: the existing core-log and coupling harness counts hold, plus the new port
section; no wire log a v2-strict reader refuses.

### M3 — the pair gates that need only the manual rung (C-live 1 CPU, 2, 3)
One pinned globe world (the three B-b bundles are the obvious pins), each gate a two-checkout
run: **gate 1 CPU** — cut → pack v2 → file → section → observe → core log v2 → file → globe
side table, twice, byte-identical logs at the same seed and cadence; **gate 2** — the generated
corpus through both sides' strict entries, each refusal leaving the receiver's state untouched
(here: `S.hash()` unchanged and nothing committed; there: side table and UI intact); **gate
3** — staleness after either world changes: a re-bake moves `packChecksum` so every earlier log
reads stale-never-current on the globe; a slice state change moves nothing on the globe. The
GPU-snapshot half of gate 1 is the globe's deliverable (its readback path, or its reasoned
reason the CPU state is the export path); the gate is pair-green only with that half answered.
Gate: a written pair record per gate, both repositories named, run directions both.

### M4 — gate 6 (fixed-seed, fixed-cadence pair run)
The 20-import identity the coupling harness already owns, run at the pair level: pinned world,
fixed seed, cadence 5, imports through the manual file path; every handoff books its ledger
(`reconciled`/`diverged`/`fresh`/`retired`), the mass identity closes to 1e-9, the clock label
follows the pack, and every cadence-built core log validates and names exactly the columns the
moved-columns predicate names. Gate: the run reproduced from both checkouts with the same
fingerprints and ledgers.

### M5 — gate 7, the C4 review
Held on M3/M4's evidence. Decides comparison-only vs any permitted feedback, and records the
decision in both repositories. This plan's position is §2 P7; the review may overturn it.
Gate: a decision record each side can point to; the roadmap's §5 line edited by whatever it
decides, and not before.

### M6 — release
Roadmap row, acceptance section, the pair records archived. `0.9.0` M0–M2 (C1 audit, host
contract, library page) may proceed in parallel with all of the above — they touch nothing
shared — but 0.9's M3 (the globe hosting the section) waits for the globe's adapter decision,
which this plan's answer carries.
