## 1. The decisions

**1. A window is not a host.** M0 measured that `COLSIM.start(window)` was refused with the
same message as any other bad host, and that §1's wording ("a document, a window or an
element") was false for the window. The contract now says what the code already did: the host
is a document or an element, and a window is refused by its own name —
`COLSIM.start does not take a window: the host is a document or an element`. The reason is
the engine's, not the page's: the controls are page-global ids, the engine paints into `#c`
inside the host, and a window is a realm, not a container — a foreign page's own `#c` would
answer to the same name. With the window refused, the window branch in `hostWindow`
(`js/sim.js`, `js/section-pack.js`) was dead and is gone.

**2. The host is required.** `COLSIM.start()` with no host is refused by name, and the
`root.document` fallbacks are gone: `hostDocument` in `js/sim.js` and `js/section-pack.js`,
`this.host = host || root.document` in `js/ui.js` and `js/section-pack.js`. A page says what
it is; `columns.html` already said `COLSIM.start(document)`. The refusals are checked before
the running loop is touched, so a refused start leaves a running engine running.

**3. The `page()` probe is gone.** M0's one page-name read was `js/section-pack.js:23`:
`page()` read `root.document` on every stop to learn "am I in a page?", then used `root` and
never the document. The question is answered by the module system instead — `page()` returns
`root` outside CommonJS and `null` under it, because those are the two cases in which the
engine's globals are or are not on the global object. The engine now reads **no** page name
off its own global: 0 reads of the 10 booked names, where M0 measured 4 (`document @
js/section-pack.js:23 ×4`). M2's "the engine never touched `document`" is therefore strict as
written, with no allowance to make.

## 3. The contract

`0.9.0-contract.md` is the deliverable: the adapter's API, written down once, in nine
sections — the shape, the host, the entries, mount, start/stop, coupling in, observations
out, mode and staleness, and what the host must not do. Twelve entries are named:

```
COLUI.build(host)            COLSIM.start(host)          COLSIM.stop()
COLCOUPLING.apply(msg)       COLCOUPLING.last            COLCORELOG.build(state, o)
COLCORELOG.json(msg)         COLCORELOG.note()           COLSECTION.mode
COLSECTION.syncLive          COLSECTION.syncStale        COLSECTION.syncPaused
```

The plan's shorthand (`COUP.apply`, `CLOG.build`) names the modules; the *globals* are
`COLCOUPLING` and `COLCORELOG`, and those are what an adapter calls — the contract names the
globals, and the harness checks the globals.

Two of the plan's lines needed code, and got it:

- **`COLUI.build(host)`** (`js/ui.js`) writes the engine's control subtree into a container
  element. The chrome is a table — `[tag, attributes, children]`, a string child a text node —
  and the builder is a dozen lines. `columns.html` keeps its static spelling, and the
  harness pins the two against each other: the built id set is the page's id set (43 ids),
  and each built control is the page's control, tag and attributes equal, the four preset
  buttons included. A host that mounts without the chrome is not supported; a host that
  wants the chrome hidden wraps the container in CSS.
- **the stylesheet is the host's.** The built chrome is semantic — ids, roles,
  `aria-pressed`, titles, placeholders — and the page's `<style>` block stays the page's.
  A host that wants the section to look like our page copies that block or writes its own
  rules for the ids; the contract says so in one line rather than shipping a second
  spelling of the CSS.

## 8. Next step

**M2 — `library.html`, the dry-run host.** One new page (not part of the `index.html` /
`particles.html` mirror rule), file:// safe, classic scripts, no build: a minimal document
that builds the chrome into a nested container with `COLUI.build`, starts the engine there
with `COLSIM.start(container)`, loads one of the three Earth bundles through the normal
`SECTION_PACKS` path, and drives a scripted coupling sequence from a second baked pack as if
it were the globe. Acceptance: a headless-Chromium smoke in the shape of
`archive/particle-page-browser-smoke-2026-10-17.md` — start, pause, step, one coupling
apply, one core-log build and placement, stop, restart; no browser errors; and the engine
never touched `document` directly, which M1 has now made a strict reading rather than an
allowance.

Two things M2 inherits that M1 has not decided: the stylesheet (the built chrome is
semantic; the page carries the `<style>` block or its own rules) and the *ids* — the chrome's
ids are page-global, so a foreign page that already owns `#c` would collide with the engine's
canvas. The contract names the ids; M2's page owns the choice.
