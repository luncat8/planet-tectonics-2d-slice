# 0.3.2 M3 log plot — inventory verdict and the visualization (test task)

Date: 2026-10-14. Base: dc465f4 (M3 melt depletion, review 0.4.2). Test task, not a milestone:
the user asked whether the big logs the commit created are really useful, and for an html plot
of them for interest. No `js/pt/`, parameters, pages or plan text was touched.

## Files

- `experiments/m3-log-plot.js` — extractor. Reads every `experiments/logs/0.3.2-M3-*.{json,txt}`,
  classifies each file (kept / twin / re-run), picks the richest json per trajectory, and writes
  `experiments/logs/m3-plot-data.json`: the inventory, one row per cell (fingerprint, gates,
  census, depletion, ms/frame), the downsampled cold-tail paths, the band tables, the excursion
  tables and per-frame samples, and the G5 event ledgers (frame, x, y, T, margin, melt, cF, cW).
  Prints the verdict the page's first panel shows.
- `experiments/m3-log-plot.html` — the page. Seven canvas panels (no library, no build):
  inventory by trajectory, frame cost against the 20 ms gate, the cold tail, the depth-band
  extrema, the mobile-melt excursions, the G5 transfer scatter and the margin histogram. Fetches
  `logs/m3-plot-data.json`, so it needs an http origin (the test task's own waiver of the
  file:// rule): `python3 -m http.server 8000` from the repo root, then
  `/experiments/m3-log-plot.html`.

## The verdict, measured

44 files, 41.92 MB, and **11 distinct trajectories** (fingerprint):

- **22 files / 20.96 MB are byte-identical `.txt` twins.** The harness writes one file
  (`HEAT_TAIL_OUT`, `pt-heat-tail.js:536`); the worklog simply re-ran each command a second time
  under a `.txt` name. md5-identical, so the pairs carry no independent evidence.
- **11 files / 10.69 MB are same-trajectory re-runs**: the five `-timed-` serial clock reads
  (their worlds are bitwise the batch ones, only `msFrame` differs), `-final`/`-final2` assert
  re-runs, `-comp` (the composition record, same fingerprint, richer event fields), and the
  pre-fix `-watch` observer.
- **The richest json per trajectory is 10.27 MB** — and 99% of that is the event ledger and the
  cold path. The reproducible claim (fingerprint, gates, census, depletion, latency books) is
  ~3 KB per cell.
- **Nothing reads any of these files.** `experiments/pt-heat-tail-check.js` reads the M2-series
  banks (`logs/0.3.2-tail-*.json`); the M3 banks are cited by prose in the worklog and report
  only. The older log convention was one human-readable `.txt` report per run; the M3 commit is
  the first to check in machine JSON, and it did so twice per run.

So: the *numbers* in the banks are the useful part (they back the report's claims), and the
*storage* is mostly not — half the bytes are a copy, a third more are re-runs, and the bulk of
what remains is one 8 559-event ledger plus one 3 226-entry cold path. A sane policy keeps one
json per trajectory (10.27 MB), or just the scalars (≈33 KB) if the ledgers can be regenerated
by the commands the worklog records.

## What the plot surfaces (the interesting part)

- The cold tail: the plain baseline bottoms at −0.489 by frame 7827; the sub-grid relaxation
  row's minimum arrives late (10927/12000) but shallower (−0.419); the water-stripping probes
  reach −1.069 / −1.137 and their temperature gate is red — they are probes, not shipping
  changes.
- The mobile-melt face: all three seed-2 crossings (50/100/500 kyr) happen while the parcel
  rises (210→81, 186→87, 314→299 km) with an entry gap near −1.4 — the transit carries the
  excess. The seed-5 600 Myr cells never cross.
- Frame cost: the five 600 Myr seed-5 cells are 12.6–15.8 ms (serial reads), but the seed-2
  mobile-melt cells at 100 and 500 kyr are 28.1 and 139.7 ms/frame — over the 20 ms gate. Those
  were measurement cells; the coarse clock is what costs.
- Water depletion collapses the G5 candidate count 8 559 → 75 (dpart 0.01) and shifts the
  population to hotter wet margins; the mass cap leaves the count near the control's (6 604)
  but delivers only 50.
