Reviewed and improved the particle-engine commit.

### Fixed the ~150 Myr map jump / high-clock noise
- Found the repair code was treating empty **nearest-node buckets** as failed coverage, even when the quadratic deposit was still valid. That moved dozens of markers and eventually triggered a whole-lattice re-deal.
- Repair now targets only genuine low-weight transfer holes, runs before advection, and only falls back to a global re-deal if local repair truly fails.
- Reset now clears repair diagnostics correctly.

### Made the clock stable
- Fluid transport is capped at **50 kyr internal substeps**.
- At `500 kyr/f`, the engine now executes ten 50-kyr fluid solves instead of one unstable 500-kyr leap.
- HUD shows `fluid Nx` and uses measured FPS for Myr/s, so the extra high-clock computation is explicit.

The new regression proves that 50 kyr/f and 500 kyr/f produce bit-identical thermal/marker state through 180 Myr, with no global re-deals.

### Addressed the mantle vs magma visual distinction
I did **not** reverse the mantle buoyancy rule: cold dense mantle descending and broader hot return flow is physically valid for the current one-phase, constant-viscosity P1 model. The missing part was a distinct melt phase.

Added a clearly labelled, no-feedback **`melt*` pressure-release indicator**:
- Only generated in hot, upward mantle in the 80–550 km decompression window.
- Segregates upward faster than the thermal mantle field.
- Displays as an orange/gold overlay; toggle via the new **melt** button or `v`.
- HUD reports its strength and source depth.
- It is explicitly an indicator, not yet conserved magma. Actual melt particles, conduits, vents, and surface accumulation remain P3 work.
