## M4 decisions

- **`ledDelam` is a named sink line, not a memo.** `CRU.delaminate` booked its shed on
  `ledCons`; the plan's HUD invariant names `ledDelam` as part of the per-lithology
  ledger, so the ledger gains the line and the balance becomes per lithology
  `active + ledCons + ledDelam + ledMixOut = initial + ledProd + ledMixIn` (design §6's
  "cumulative sinks" carries one account per sink mechanism). The old balance formulas
  were updated statically exactly as M3 did: `ledger-check` (4), `m2-check` (2 formulas +
  the three delamination fixtures + the pristine/quiet ledgers), `edifice-bench` and
  `ore-bench` (snapshot + formula each). Delamination's own contract ("booked so the
  ledger says where the rock went") is unchanged — only the line is named.
- **The JSON save is E3's session envelope.** `Checkpoint.saveSession()` is one JSON blob
  whose runtime payload enumerates every typed array and scalar of `S` plus the clocks,
  the RNG words and the sliders; `loadSession` restores it bit-identically. The planet
  bar's save / load buttons move that same file the section panel's save session moves —
  one codec, one transport, no second serializer. The save-bench asserts the coverage
  literally (record count == every `S` typed array; value slots == scalars + recon + 7
  clocks + 10 parameters).
- **Checkpoint v9.** The schema gained `ledDelam` and the value block's tenth parameter,
  `SLAB.ready` — the ribbon machinery's own run flag (same class as `RNG.gs/gh`, read by
  `COL.consume`'s ribbon branch). `load` also drops `COL.floorClassValid` so the settled
  C-C classification recomputes from the restored state instead of inheriting whatever
  the live process left (it is a pure function of `S`). Neither leak can bite the kernel
  order as shipped (K1 always precedes K4 on a running frame, and K3/K4 are dt-gated),
  but a restored world must present the same branch to any caller, and the done protocol
  now pins the whole value block byte-for-byte. No legacy reader: v8 is refused by
  header, as v7 was.
- **The diag is read-only.** `S.massInto(m)` fills a caller buffer (`S.mass()` keeps
  filling the state's own scratch), so the 2 Hz HUD repaint cannot change `S.hash()` —
  the property ore-ui already gated. `SIM.diagReset()` re-bases the per-lithology ledger
  identity (each lithology's implied initial mass) at every world rebuild: `SIM.reset`,
  `Checkpoint.load`, and a laid cut (`section-pack.reconstruct`).
- **Min gap** is the contact floor's own contract: ordinary inter-plate pairs at
  `gFloor * w0` with the floor's documented `floorTol` slack (the same bound the M2
  long-run gate uses), and closing C-C conveyor pairs at `crushFloor` — reporting both
  minima in `w0` units. Intra-plate gaps are rigid and not floored.
