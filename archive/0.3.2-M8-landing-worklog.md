## Steps

1. **The constant and the rule.** `depBound: 0.25`, deposit-scoped. The kernel implementation is
   the probe's own arithmetic, copied rather than re-derived: one field snapshot per frame into
   `tfP`, the cap read on the post-gather temperature against `tfP ± depBound`, the withheld
   increment keyed by node and side, placement over the 3x3 stencil block on live enthalpy with
   each recipient's own field-relative headroom, and the giveback to the capped parcels when the
   block cannot take it. Per-node totals are preserved, so `S.hLedger` closes as before. The
   scratch arrays are allocated once per mesh size (`bdScratch`), not per frame.
2. **The landing gate, before any re-bank.** An unprobed `baseline` run at 50 kyr/frame over
   600 Myr on the three M7 worlds:
   `baseline 0 600 --seed 5`, `--seed 3`, `--seed 1`. Each must reproduce the M7 candidate bank
   field for field. They did, on the first run:
   - s5 `1808048552219233`, s3 `3305588838878544`, s1 `5025891284893073`;
   - events, `hottest`, `census`, `heldJoin` and every diagnostic equal the M6 candidate banks;
   - the kernel's counters equal the probe's totals: 879,915 / 837,390 / 765,851 caps,
     50,744,148 / 44,278,273 / 49,732,506 placements, 67 / 14 / 68 givebacks, 65 / 14 / 45
     short blocks, 7,795.6 / 6,006.8 / 6,991.6 km²·H returned.
3. **The banks.** `0.3.2-M8-landed-{s5,s3,s1}-600.json`, each the harness's own console record
   beside it. The s5 run also demonstrates the gate: 0 refusals, all books closed, deposit phase
   T ≤ 1.1136, worst held gap 0.2503, 16.27 ms/frame.
4. **The checker.** M8 section added after M7; `node experiments/pt-heat-tail-check.js` exit 0,
   **17 PASS lines** (16 before, one new). The `--assert-landed` flag added to the runner; the
   old `--assert-baseline` and `--assert-m2` stay as the pre-M2/pre-M8 trees' gates, per the
   plan's re-bank rule.
5. **Series.** P3 42/42 (883.6 s), P4 29/29 (1,950.5 s, the integrated leg 17.81 ms/frame), the
   0.3.1 leg 37/37 (111.3 s), page parity 53/53 and the whole-series acceptance 49/49 re-ran
   green on the shipped kernel; results in the report's §4. The guard's measured line and the owners' `P.depBound = 0` isolation are the
   addendum below.
6. **Hygiene.** The three M7 trace banks over 4 MB compacted by `log-hygiene.js --compact
   --apply`: 45.26 MB -> 3.76 MB, rows 120,600 -> 1,717. The read set is preserved (per-id
   scalars, stride spine, deliveries, phase changes, last frames, `caps[]`); `why` 1/2/4 and the

   the M5 banks stayed whole because their checker reads consecutive-frame rows. The directory
   went 89 MB -> 44.15 MB (1091 files, the two M8 trace logs included), with nothing deleted:
   the 41.5 MB of trace bytes was rewritten by a summary transform, not lost as evidence.

## Addendum — the guard's residue

The P4 integrated leg's no-penetration line was the one red left after the series. Replayed and
measured: **2 pairs at 0.9971 and 0.9969 of `contactHard` on frame 4,130 of 6,000** (t = 206.5
Myr). The replay shows one marker pressed between two others on adjacent columns: the sweep's
equal-and-opposite push halves the shared overlap each pass, so the 3-sweep cap turns an initial
2.3% overlap into 0.3%. The base tree (`36b07cc`) leaves 0 on the same leg. The cap is older than
M8 at longer horizons: the base seed-5 600 Myr world leaves **280 residue frames / 286 pairs**,
the M8 world **156 / 157**, M8 s3 **26 / 29**, M8 s1 **112 / 115** (fingerprints equal to the
banks, so these are the banked worlds).

Decision: no constant changed and no bank moved. `pt-p4-check.js` now reads the guard's own table
inside the pass (a read-only wrapper, because a later kernel can compact the pool) and asserts the
measured bound — at most one frame, at most two pairs, no pair closer than 0.99 of the radius —
printing the frame, the ratio and the push count. The kernel, `ctSweep: 3` and every fingerprint
stay frozen; clearing the cap (~20 sweeps) is the guard owner's call. Re-run: ALL PASS (23).
