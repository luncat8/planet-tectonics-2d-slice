# 0.4.1 M5 correction + continuation report

Reviewed `1a4f0ef` and corrected the M5 step-2 importer before extending the live path.

## Review fixes

- `COUP.apply` now edits the actual bed stacks by lithology class and derives
  `hFel` / `hMaf` / `hSed` / `hTot` with `COL.sums`; imports are no longer cache-only or undone by
  the next kernel. Positive imports become dated reconcile beds rather than inflating the seed
  bed; class shrink marks the newly exposed contact as an unconformity.
- Paste, button and file use one checksummed reader. Unsigned messages, foreign paths and imports
  without an active reconstructed section are refused before state mutation.
- `pathChecksum` is now a stable geographic-line identity, independent of time, fields and source
  resolution. Each coupling message still has its own body checksum.
- Reconcile bookkeeping is cumulative and consistently volumetric. Per-import terms close
  `before + added + fresh - removed - retired = after`.
- The 20-import test now evolves between messages, recomputes caches from beds, and retains each
  import's result instead of rereading the final one. Worst relative identity error:
  `1.675e-15`; worst matched-column bed retention: `98.9 %`.
- Coupling targets follow Lagrangian columns and survive checkpointing; checkpoint binary schema
  is now version 2.

## Continued M5

- Added C3's K2 owner: live messages prescribe rigid section-plate velocities from the
  width-weighted globe intervals. Detach/reset/restore cleanly return K2 to the standalone solve.
- Added the handshake ladder: `postMessage` → `localStorage` → `clipboard/file`, with the active
  rung always shown in the HUD.
- Live payloads still pass the same checksum/path reader as manual payloads.
- Added path-guarded clock pause/resume. A paused globe pins section geologic time and is labelled
  `live · globe paused`; cadence prevents running ahead of the latest snapshot.
