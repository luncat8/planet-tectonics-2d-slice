# 0.3.0 P3.4 — flight, landing and welding

P3.4 completes the conserved eruption path. Chamber melt now travels through a vent schedule,
becomes a real airborne pool parcel, follows a bounded wall-clock arc, collides with the physical
terrain, returns as landed material, cools through the heat ledger, and welds through the existing
crust law. No visual-only edifice or material copy is kept.

Primary gate: `experiments/pt-p3-flight.js`, **50/50 checks passing**. Full serial suite:
**14/14 harnesses, 558 checks passing**. Logs are `experiments/logs/0.3.0-p3.4-*.txt`; detailed
decisions and failed trials are in `archive/0.3.0-p3.4-worklog.md`.

## Interfaces

New global: `PTFLIGHT` from `js/pt/flight.js`:

- `surfaceY`, `launch`, `emit`, `advance`, `land`, `mergeTarget`, `cool`, `run`, `count`.

New settings:

- emission: `emitEff`, `emitBlast`;
- trajectory: `flightFrame`, `flightDtMax`, `flightG`, `flightVyEff`, `flightVyBlast`,
  `flightVxEff`, `flightVxBlast`, `flightLift`, `flightPx`;
- deposit: `depositCoolT`, `depositCoolTau`, `depositCoolDepth`, `depositMerge`;
- compatibility: `mergeCompF`, `mergeCompW`.

New state bookkeeping:

- transactions: `tx.emit`, `tx.land`;
- throughputs: `thr.airDr/airCr`, `thr.landDr/landCr`;
- all are reset and included in the complete-state fingerprint.

`SIM.step(wallDt)` now accepts an explicit presentation interval; `SIM.wall(wallDt)` advances
only existing flight while geology is paused. `PTPOOL.compatible` owns merge compatibility, and
`PTPOOL.merge` now conservatively carries mechanical state and returns the survivor's true slot
after dense compaction.

The page renders flight and deposits separately, reports their stocks and throughputs in the HUD,
and keeps `index.html` / `particles.html` byte-identical. Visual evidence is
`archive/p34-lid-10Myr.png`.
