## 1. Method

- **A bare VM context is a browser realm without a DOM.** Its global has `window` (itself) and
  nothing else: no `document`, no frame clock, no timers, no `console`.
- **The global set is two sets.** The first is the global's own properties, diffed per script
  for attribution. The second is the global lexical scope (top-level `let`/`const`/`class`),
  which no property walk sees. It is read through an in-process `inspector.Session`
  (`Runtime.globalLexicalScopeNames`), with each context found by the name given to
  `vm.createContext`.
- **Page reads are booked, not assumed.** For B and C the context's global carries accessor
  traps for ten page names (document, location, localStorage, requestAnimationFrame,
  cancelAnimationFrame, setTimeout, setInterval, addEventListener, removeEventListener,
  postMessage). Each read is booked as `name @ file:line` from the getter's stack, and
  `typeof` still answers `'undefined'`.
- **C's host is columns.html's own markup.** The harness parses the ids, attributes and preset
  buttons out of the page into a document with its own window. That window owns the frame
  clock and the listener book, so the two counts C asserts are read off the host. The context's
  global keeps no DOM.
- **D reads the globe by revision.** Every file comes from `git show <rev>:<path>`, so the
  checkout's HEAD never matters, and the page is their `index.html` `<script>` list in order.
  "Shared" means a `port/*.js` that both pages load and whose bytes at that revision equal our
  `port/PORT.json` sha256. The tip is the counterpart's branch tip (origin/HEAD), as
  `experiments/upstream-drift.js` does.

## 3. C — one host, one loop

The host has 43 ids, presets def/ovw/cru/bas and a 1280×560 canvas.

- `start(host)` leaves 1 frame pending and binds 22 listeners (`COLUI._listeners`).
- After 2 ticks, a second `start(host)` returns the same object with 1 frame pending and 22
  listeners, at frame 2.
- 2 more ticks give frame 4: one loop, not two.
- `stop()` leaves 0 frames and 0 listeners. A frame already in flight then does nothing, and a
  second `stop()` is a no-op.
- The restart has 1 frame pending, 22 listeners, frame 0 and t 0. After 4 frames it replays the
  first start bit for bit: `2923187299 rng 1462510275,1210816365,17857332,318624663 t 0.2`
  (`COLS.hash`, the RNG state, t).

With a host in hand, the one page name the engine reads off its own global is
`document @ js/section-pack.js:23 ×4`. `page()` reads `root.document` on every `SEC.stop()`
(start's non-section branch and stop) to learn whether it runs in a page, then uses `root`,
never the document. M2's "never touched `document` directly" has to allow this probe, or M1
replaces it with the host's window.

**The collision.** Ours is `js/data/deposit-economics.js`, v1, frozen, sha256
`97008fa9e8b6681d7ce98a1c5196e1d1b2e2d22c615e1e1565f2c3d919876140`, a data table plus
`screen`/`describe`. Theirs is `js/data/deposit-economics.js`, v2, sha256
`6ea62830e8a232640fb6deb6868ecd22f24156276249661f6e7e6a078facb3d6`, method-based (`methods`,
`method`, `value`, `money`, `verdict`). The same path and name hold two different files, and in
one document the later `var` takes the name. It is not cosmetic: their v2 methods read the
global `DepositEconomics` at call time, so if our v1 loads after theirs, their own `screen({})`
throws `TypeError: econ.method is not a function` (measured in scratch). Their `js/deposits.js`
and `js/instruments.js` capture the name at load; ours (`js/deposits.js`) does too, so loaded the
other way, our deposits capture whichever object holds the name at that moment.

**Why the 0.4.4 proxy missed it.** `archive/0.4.4-agreement-worklog.md` §2.1 grepped their
`js/*.js` top-level declarations against our 25 `COL*` names, so `js/data/` was outside its scope
on both sides.

**Decision (the user's, this session): record.** `RECORDED` names `DepositEconomics` with both
paths. D asserts that our page ∩ theirs = the shared names ∪ the recorded ones, and re-checks
on every run that each recorded name is still two different files. A new collision, or this one
resolving, turns D red until the record moves in the open. The two options not chosen were
strict (D red until it is resolved) and renaming ours now (that would edit the engine files
`js/deposit-core.js` and `js/deposits.js`, outside M0's scope).
