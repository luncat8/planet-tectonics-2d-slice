# 0.4.1 M5 step 2 review — `1a4f0ef`

## Verdict

The envelope and read-only delta measurement from step 1 are sound enough to extend, but the new
`COUP.apply` path does not yet implement C4 and its experiment does not exercise the claims in the
report. The page must not advertise a successful reconcile until the critical findings below are
fixed.

## Findings

### Critical — the import edits caches, not geology

`COUP.apply` writes `hFel`, `hMaf` and `hSed` directly. It does not edit `layTh` / `layLi`, does not
update `hTot`, and does not call `COL.sums`. Those thickness fields are documented caches of the
bed stack. The state is inconsistent immediately after an import and the next kernel that calls
`COL.sums` restores the old values, silently undoing the message. This also means the report's
claim that beds stay while aggregate crust follows the globe is false: no bed records the added or
removed material at all.

Required correction: grow and remove material through bed-stack operations, preserve unrelated
beds and deposit indices, then derive every aggregate from the stack.

### Critical — the page bypasses both wire guards

The paste handlers call `JSON.parse` and then `COUP.apply`. `validate` deliberately permits an
unstamped in-memory message, and `apply` neither requires a checksum nor compares
`pathChecksum` with the active cut. Consequently the page accepts an unsigned message and a
validly checksummed message for a different transect, despite both being explicit M5 refusal
gates.

Required correction: one coupling-text entry point must run `COUP.parse`, require the active pack
identity, and refuse before any state write.

### High — the 20-import gate is a false positive

Section E in `experiments/coupling.js` does not simulate the sequence described by its comments:

- section D's import-cost loop leaves `S` hard-reset to `packs[20]`; section E then applies messages
  1 through 20 to that one static state without advancing the section between imports;
- `SEED.ledger(packs[20])` compares the final pack with the unchanged `hTot` cache, so the 1 % mass
  check passes independently of the fields `apply` changed;
- the second loop reads the one final `S.recon` value twenty times, rather than retaining each
  import's values;
- `maxFresh <= SEED.nCut` and `maxRetired <= msg0.crust.length` are bounds guaranteed by the loops,
  not evidence that stacks survived;
- the plan requires a `1e-9` identity; the experiment accepts 1 % and never recomputes aggregates
  from beds.

Required correction: re-layout message zero, evolve between every import, capture each result at
the import, call `COL.sums` after each apply, and close `old + added - removed = new` at `1e-9`.
A deliberately tagged bed and deposit must survive a matched-column reconcile.

### High — the ledger is not the ledger described by the plan

`freshVol` and `retiredVol` are calculated and discarded. `fresh` and `retired` store counts while
the surrounding fields store volumes; `diverged` is always reset to zero; every import resets all
five fields even though §8.1 calls the displayed fractions cumulative. `totalReconciled` in the
experiment is likewise calculated and unused.

Required correction: distinguish per-import residual from cumulative volume, give every field one
unit, and expose signed in/out values (or an equivalent result) so the mass identity is testable.

### High — a no-world import reports success

With the page not reconstructed, the paste path passes `nCut: 0`. `apply` then mutates no columns,
resets the reconcile record, and returns success. A coupling message needs a verified active cut
and a legal reconstructed state.

### Medium — implementation and report drift

The module header still says that nothing in the file mutates section state and that applying C4
is the next step. The report says validation and bed preservation are complete. The two duplicate
paste branches have already diverged from the pack's single-reader rule and make this kind of
claim drift likely.

## Validation baseline

Before changes, all existing harnesses pass, including `experiments/coupling.js` with 88 checks.
That green baseline demonstrates the coverage gap above rather than validating C4.

## Recommended order

1. Make `apply` a checksummed, path-guarded, atomic bed-stack reconcile and replace section E with
   an actual import cycle.
2. Add the live-state metadata and HUD line only after the corrected C4 gate closes.
3. Continue M5 with C3/clock handshaking, the transport ladder, then the observation log; do not
   build those paths on the cache-only importer.
