**The refactor** (`js/section-pack.js`, the loading block only):

- `decodePack(text)` — the one decode entry. Parse, type-guard, `SP.normalize → SP.quantize →
  SP.validate → SP.verify`; a refusal names the reason and leaves the shown cut untouched. The
  body is still the v1 pipeline; B4 swaps it for `SP.decode(text)`.
- `load(text)` (paste, file) — one parse to route a coupling message, then
  `accept(decodePack(wire))`: no second decoder on the object the sniff already produced.
- `loadPack(pack, origin)` (a bundled `SECTION_PACKS` object, a caller's object) — type-guard,
  typing and quantisation in place, `SP.verify`, then `accept(decodePack(SP.encode(pack)))`:
  the object path is the text path with the checksum proven before the round trip, because a
  value the field checks cannot see (NaN never survives JSON) must be caught before it becomes
  a zero. **One decoder, not two.**
- `accept(pack, origin)` — the shared tail the old `loadPack` carried: `SEED.measure` (a
  measurable-but-unplaceable window keeps the pack and stays the strip), the state swap, the
  reconstruct. No behaviour change; the strip, the overlay, the assumption ledger and the
  clock-off window rule are the harnesses' own readings above.

**One plan correction, measured.** The plan (§3 A2, F4) words the object path
“`verify(raw)` then `decodePack(JSON.stringify(raw))`”. In v1 that order is impossible:
`SlicePack.checksum` reads a field array through its `.buffer`, a plain JS array has none, so a
raw bundled object checksums over HEAD+TEXT only — measured `f464971e2fd0320f` against the
pinned pack's stored `5e6a558adccfde21`, i.e. **every bundled pack would be refused**. The v1
object path therefore types and quantises in place *first* (what the old code and `SP.decode`
already did), then verifies, then decodes; B4 deletes the two typing lines and the method
becomes exactly the plan's `verify(raw) → decode(text)`. Two smaller notes: the object path
stringifies through `SP.encode`, not bare `JSON.stringify` — a typed array stringifies as
`{"0":…}` (the codec's own `plain` replacer exists for this), and for the plain-array bundles
the two produce identical bytes; and the NaN corruption is still refused before the round trip
(checksum mismatch), which is the protection the plan's order was after. The harness's one
changed line is that refusal's reason text (`field pot is not finite at 7` →
`checksum mismatch: the pack was edited or truncated`) — printed, not asserted; the refusal
itself, its atomicity and the counts are unchanged.
