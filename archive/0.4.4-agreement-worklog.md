## 2. Measurements the plans are written from

1. **The globe's page globals at `3c960e7`.** Approximation method: top-level `var`/`function`
   declarations across their `js/*.js` (a proxy — real load semantics belong to the M0 harness
   of `0.9.0-plan.md`, which loads the scripts in a VM and reads the actual global set). The
   proxy yields ~120 names, all short and un-prefixed (`Params, Grid, State, Columns, Sim,
   Slice, SliceSP, Checkpoint, Renderer, …`). Intersection with this engine's 25 `COL*`
   globals: **empty**. The only shared name at all is `SlicePack` — the same byte-identical
   `port/slice-format.js`, which the host page loads once by design.
2. **`SECTION_PACKS` is ours alone.** Grep over their tree at the pin: no occurrence. The name
   cannot collide today; M0-D keeps the check as a drift gate.
3. **`SlicePack.fnvText` is not exported** (the export list at `port/slice-format.js`: `round,
   make, seal, validateRaw, validate, verify, checksum, pathChecksum, encode, decode, hostCode,
   edgeCode, edgePolarity, setGap, circle…` — no `fnvText`). This is what grounds proposal P3:
   a v2 core-log codec cannot borrow the pack's hash helper through the public surface, so the
   protocol module owns its hash (domain string baked in), which is also what their §2.1
   "independently testable" asks for and what their objection to v1 names ("a private section
   FNV helper") rules in.
4. **C1 is already in place.** The §8.6 clauses were re-checked against the tree before
   scoping 0.9.0: 25 engine files, each an IIFE exporting exactly one `COL*` global with the
   guarded `module.exports`; `SIM.start(host)` resolving document/window/element hosts with
   the named throw and no self-start (`columns.html`'s one inline `COLSIM.start(document)` is
   the bootstrap). The plan therefore spends its C1 budget on proof and contract, not on a
   refactor that is not needed. Lesson recorded in `findings-pitfalls-skills.md`.
5. **The validation laws already correspond.** Their §2.1 bullet list and `js/core-log.js`'s
   implemented law line up item for item (sum tolerance, finite and non-decreasing formation
   times across non-`intr` contacts, real lithology, positive thickness, ascending unique
   `sKm`, missing checksum / foreign version refusals). Their sketch's two deltas from v1 are
   exactly P3 (module/hash ownership) and P4 (named schema). The protocol text is a port of a
   law both sides have already stated — which is why this can be a decision, not a design.
6. **Their §5 manifest repairs are still owed on both sides** (their stale `section-reader`
   note; the pin set). P2 folds them into the one coordinated bump their §5 itself recommends,
   so the negotiation pays two debts it was already going to pay.
