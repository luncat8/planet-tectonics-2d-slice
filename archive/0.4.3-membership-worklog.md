# 0.4.3 — Worklog: rebuild section plate membership at coupling import

The job of `0.4.3-draft.md` §4, done in the three steps the draft wrote down before any
run: **M0** prove the stale membership with one fixture, **M1** rebuild membership at
import, **M2** accept it against the exit criteria written in advance. Owner harness
`experiments/coupling.js` (sections M and N); no other file of the exchange was touched.

## M0 — the premise, measured before a line was changed

Fixture: `SEED.layout(pack0)` (the pinned world, 12 plates of 44 columns), then a
self-message (`SEED.exportSection` → `COUP.fromPack`, so the message's globe ids *are* the
section's own local indices), then the same message with the seam between plates 2 and 3
walked 625 km (8 columns) to the right — a valid message still: the two intervals share the
moved edge and both tables still end at the arc.

Read against the unmodified `COUP.apply` (scratch probe, not committed):

| reading | value |
| --- | --- |
| columns the message now puts on the other plate | 8 (columns 132–139) |
| columns whose `S.colPlate` changed | **0** |
| plate 3's speed after `COUP.slave` | **12 544 m/Myr**, was 96 |
| the 8 crossed columns' `colU` | 12 544 (the blend), not 68 556 |
| `S.recon.bndLost` for the import | **+1**; `S.edge[139] = none` |

So both halves of the draft's §3 claim hold, and the second is the worse one: the crossing
the message reports (`bnd 4`, a collision) lands *inside* local plate 3, `syncEdges` has no
seam that separates two plates to put it on, and the boundary is simply not drawn. The
speed error is not confined to the crossed columns either — one boundary walked 8 columns
and all 44 columns of the plate it entered moved at a 130× wrong speed, because `slave`
averages the message's velocities per existing plate.

## M1 — the rebuild (`js/coupling.js`)

`COUP.replate(st, msg, n, closed)`, called in `apply` after the geographic walk and before
`syncEdges` (the seams `syncEdges` paints have to separate two plates, so membership comes
first). It reuses the walk `apply` already made (`midKm`) and the seed's own rule:

- every column takes the `msg.plates` interval owning its arc midpoint;
- contiguous runs of one globe id are one local plate;
- a closed cut's first and last run of one id are one plate (`recon.plateWrap`);
- more runs than `plateCap` merges the narrowest into its wider neighbour
  (`recon.shortPlateMerge`), as the seed does;
- a plate inherits `plU`/`plUP`/`plDmg` from the old plate that owns most of its ground —
  an import moves columns, it does not prescribe kinematics (that is C3's, while the
  message is the live one);
- `SEED.platesFrom` is kept true, so the section can still name the globe plate of every
  local one (it is also the map the first import compares against).

Two things the draft did not know and the run found:

1. **Gap rows.** The v2 codec canonicalises a gap row's plate id to 0 (`SP.setGap`), and
   the pinned cut has two of them at 28 911 km and 36 795 km, inside plates 8 and 10. Taken
   literally they are two runs of "globe plate 0" and the section came out with 16 plates
   and 142 columns replated on the very first import. The seed reads the same thing from
   the sample's own `alive` flag; a message carries crust and no flags, so the gap is read
   as *an interval every one of whose crust rows is empty*, and it takes the id of the
   nearest interval before it that does carry crust, wrapping on a closed cut — the seed's
   carry-forward at the message's resolution (`gapTable`, `carrierId`,
   `recon.plateGap`). With that, the first import of the pack the section was laid from
   moves **0** columns: the seed's rule and the message's agree.
2. **The midpoint rule is the nearest-seam rule.** The run boundary a column's midpoint
   falls on is exactly the section seam `syncEdges` picks as nearest to the crossing, so
   the membership and the painted edges cannot disagree by half a column. This is why
   `bndLost` comes back to 0 on the M0 fixture instead of trading one lost boundary for
   another.

Ledger, all on `S.recon` and booked only when the membership actually moves (an import
that rebuilds what is already there is not an event — the same eight cap merges would
otherwise be a new line every cadence): `plateImports`, `plateCrossed`, `plateAppeared`,
`plateVanished`, `plateWrap`, `plateGap`. What the section had, in the globe's own names,
is the previous import's record, or the seed's map on the first one; the section's own
events renumber its plates between imports without naming a globe id for what they made,
and those columns are booked as the difference they are the next time the globe speaks.

Membership is not geology: no stack, deposit, vent, ghost or ribbon is touched, and the
crust identity `before + added + fresh − removed − retired = after` still closes because no
bed moves (asserted on every import of sections M and N).

## M2 — acceptance, run against the criteria of the draft

`experiments/coupling.js`, 12 new checks (150 total, was 138):

| criterion | where | reading |
| --- | --- | --- |
| the fixture is a message the section would accept | M (3 checks) | a self-message rebuilds the membership it already has (0 columns off, 0 booked); the walked seam is still a valid message; and it names a boundary 8 columns (625 km) from where the section had it |
| (a) the crossed columns land on the new plate | M (2) | 8/8 replated, the other 504 columns untouched, 8 booked; the reported crossing lands on seam 139, which separates plates 2 \| 3, `edge 4` of `bnd 4`, `bndLost +0` |
| (a) and take the new plate's speed under `slave` | M (2) | the import itself moves no velocity (every plate keeps the speed of the ground it became); under C3 the 8 columns run at 68 556 m/Myr and the 44 columns of the plate they left stay at 96 |
| (b) an unchanged second import changes no membership | N (1) | 0 column/edge changes, 0 ribbons, 0 imports booked, 12 plates |
| (c) a boundary crossing the wrap | N (1) | 6 columns crossed at the start, 34 columns on the one wrapped plate, `plateWrap 1` |
| (c) a plate appearing | N (1) | 3 columns on new globe plate 118, 12 → 13 plates, `appeared 1`, `platesFrom` names it |
| (c) a plate vanishing | N (1) | 44 columns of globe plate 5 absorbed into 4, 12 → 11 plates, `vanished 1` |
| (c) an open window | N (1) | 158 columns, the two ends on plates 0 and 8 under one globe id, `plateWrap 0`, terminal edge unset |
| (d) the existing suite stays green | whole series | `coupling.js` 150/150, `coupling-link.js` 11/11, `acceptance.js` 49/49 delegating to every owner harness |

Every one of the twelve also re-reads the crust identity of that import
(`before + added + fresh − removed − retired = after`, relative error ≤ 1e-9), which is how
"membership is not geology" is asserted rather than claimed.

An `INFO` line in section M keeps the M0 reading beside its own fix, so the harness says
what the stale membership did (8 columns stranded, 44 dragged at a 12 544 m/Myr blend, the
reported collision booked lost) without a reader having to re-run the probe.
