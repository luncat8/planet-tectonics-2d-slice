# 0.3.0-P3.0 report — paste-back

Request (verbatim): "0.3.0‑P3 (conserved melt / eruption pool‑ledger for the particle engine) —
the pile rule it was waiting on is now in place."

## What landed

- **The pool** (`js/pt/pool.js`, global `PTPOOL`): admit / split / merge / remove, with
  refusals counted and never silent; naive per-frame inventory and a compensated gate pass.
- **Phases** (`params.js` `PH`): mantle, melt, airborne, landed deposit. Every kernel routes
  by phase through flat masks (`PH_GRID`, `PH_ADV`, `PH_SOLID`). Airborne parcels are in no
  pass: wall-time only.
- **State** (`state.js`): id, phase, enthalpy, composition and melt per parcel; the heat
  ledger `hLedger`; counters `tx`; capacity `partBase` 23552 → `partCap` 28263 at 256×24.
- **HUD**: `phase mantle N melt N air N dep N   mass … km2   H …   hLedger …`, plus
  `refused N` only when the reserve has run out.
- `index.html` and `particles.html` stay byte-identical.

## The numbers that matter

- Routing table, measured (`pt-p3-routing.js`): airborne in no pass; melt conducts and repairs
  but does not ride the flow map; an above-surface deposit is not repair material.
- Live 400-frame run with 800 airborne and 600 deposits in the pool: no NaN; mass unchanged
  to rounding; enthalpy against the wall book at intake/wall 1.0000; coverage 0 holes; clasts
  bitwise unchanged; phase counts exact.
- Pool transactions (`pt-p3-pool.js`, 70 checks): 4711 splits fill the reserve exactly with
  mass drift 1.3e-13 relative; refusals change only the counter; replay is bitwise.
- The shipped frame at 256×24: 11.3 ms (`pt-check`); with the reserve filled, 11.8–13.7 ms
  across runs (budget 14 ms).
- No typed-array construction and no ArrayBuffer growth over 400 frames at capacity.

## Defects caught in review

- A swapped Fast2Sum branch in the compensated sum: the "compensated" pass was naive. The pool
  fixture had not caught it because it compared the pass with itself. Fixed, and the fixture
  now carries a direct Neumaier cross-check, mutation-tested (the bug reinserted fails it).
- The routing probe's crust and repair setup was wrong on the first pass (a hot, unaged
  parcel; repair after advection). Corrected in the probe, not the engine; the table was then
  checked against the expectation written before the run.
- Several harness-side errors (naive tally against a compensated gain; a total compared with a
  per-call threshold; invented pass thresholds; a stale marker count in `pt-ui`). All fixed.

## What is not decided

- **The reserve is not frozen.** The candidates (0.05 / 0.03 / 0.12) stay, because the
  benchmark does not reject them, but its price sits inside the sandbox's own frame-time
  noise (windows spread 2–37%). Re-run `experiments/pt-p3-budget.js` on an idle machine and
  freeze from the shipped-rung row.
- **Above-surface material is reflected** by `keepInside` at the top wall, back into the mesh.
  Whether an edifice stands inside the fluid domain or above it is a P3.4 landing decision.
- The 512×48 and 1024×96 rungs are over the 14 ms budget with or without a reserve. The plan
  makes no promise there.
- Allocation is gated for typed arrays only; object and closure allocation is by reading.
