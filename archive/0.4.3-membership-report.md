# 0.4.3 — Report: the section now takes its plates from the globe

The one open block before live sync is closed. Report of the job `0.4.3-draft.md` §4 scoped;
worklog `archive/0.4.3-membership-worklog.md`.

## What was wrong, in one sentence

When the globe said "this plate boundary has moved", the section moved the *drawing* of the
boundary and left the columns under it on the plate they had — so from the next frame it
dragged them at a speed belonging to a plate that no longer covered them, and it could not
draw the new boundary at all where it now fell inside one of its own plates.

## The measurement that proved it (M0)

The section's own membership, exported as a message the globe might have sent, with one seam
walked eight columns (625 km) to the right:

| | before 0.4.3 | after 0.4.3 |
| --- | --- | --- |
| columns that changed plate | **0 of 8** | 8 of 8 |
| speed of the plate the boundary entered | — | 96 m/Myr, untouched |
| speed of the plate the columns left | **12 544 m/Myr** (a blend of 68 556 and 96) | 96 m/Myr |
| speed of the 8 crossed columns | **12 544** | 68 556, the plate that owns them |
| the collision the message reports | **booked lost** (`bndLost +1`), edge `none` | lands on seam 139, `edge 4`, `bndLost +0` |

The speed error was not local: one boundary walking 8 columns moved all 44 columns of the
plate it entered at 130× the right speed, because the section averages the globe's
velocities per plate it already has.

## What landed (M1)

`COUP.replate` in `js/coupling.js`, called from `COUP.apply` before the edges are painted.
A plate is one contiguous run of one globe id along the line — the seed's own rule — so the
message that moves a boundary moves the columns with it, and:

- the crossing now always lands on a seam that separates two plates (the run boundary a
  column's midpoint falls on *is* the seam the edge painter picks);
- a plate keeps the speed of the ground it became, so an import moves no velocity — speed
  is still C3's to prescribe while a message is the live one;
- stacks, deposits, vents, ghosts and ribbons are untouched, and the crust identity still
  closes, because no bed moves.

Two things the run found that the draft did not know:

- **holes in the cut are not plates.** The pack format writes a gap row with plate id 0, so
  two holes in the pinned cut read as two extra "plate 0" plates and replated 142 columns
  on the first import. They are read from the crust now (an interval every one of whose
  crust rows is empty) and take the plate they interrupt: the first import of the cut the
  section was laid from now moves **0** columns.
- **which plate went where is written down.** Six lines on `S.recon` (`plateImports`,
  `plateCrossed`, `plateAppeared`, `plateVanished`, `plateWrap`, `plateGap`), booked only
  when the membership actually moves, so an unchanged import books nothing.

## Acceptance (M2), all written before the run

`experiments/coupling.js` sections M and N: 12 new checks, 150 total.

- the walked-boundary fixture: membership, the seam, the speed, and the identity, all above;
- an unchanged import changes nothing at all (0 columns, 0 edges, 0 ribbons, 0 bookings);
- a boundary that walked across the cut's own start leaves **one** plate wrapped over the
  seam (6 columns crossed, 34 on the wrapped plate);
- a plate the globe newly names appears (12 → 13 plates), one it takes off the line vanishes
  into its neighbour (12 → 11), and the section can still name the globe plate behind each
  of its own;
- an open window never wraps its two ends into one plate, however the ids fall;
- the existing suite stays green: `coupling.js` 150/150, `coupling-link.js` 11/11, and
  `acceptance.js` 49/49 delegating to every owner harness of the series.
