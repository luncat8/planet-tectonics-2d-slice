## 1. What the bake reads, and why

`tools/earth/bake_section.py` (new, here with the generated bundles; the plan lists it under the
counterpart's `tools/earth/` — the file header says so, and the user carries it over). It reads
the **baked Earth pack** (`js/data/earth-*.js` of `planet-geotectonics @ d909476`), not the raw
9.7 MB of sources and not a sim run: the pack is the source the viewer sees, so "the baked profile
equals the source pack's cells" is true by construction — and the post-bake check re-asserts it
sample by sample (sKm, z, hFel, hMaf, wet, plate against the cell) instead of trusting the
construction.

The walk is the raster form of `0.4.1-plan.md` §3.2: sample the great circle at a third of the
**local** cell spacing (a cell cannot be jumped), bisect each cell crossing to 1 m of arc, one
sample per crossed cell, each carrying the arc it spans, the first and last run merged when the
circle closes onto its first cell. An adjacency guard (a crossing to a non-neighbouring cell
splits the step and retries; a second failure throws) is what keeps the §B no-jump gate honest
when the cells narrow toward a pole; the bake refuses a circle that would pass over a pole, where
the equirectangular raster degenerates.

**One owner for the format:** the bake assembles plain numbers; `tools/earth/stamp.js` runs them
through the shared `port/slice-format.js` (normalize → quantise → checksum → validate → verify →
canonical text). A baked pack is the same object a drawn pack is, with a different `source`
block. Neither the bake nor the stamp touches a field the format does not name.

## 2. Field honesty of a static bake

A static snapshot carries no accumulated dynamics, so the bake says that in the bytes rather than
inventing it:

| field | value | from |
| --- | --- | --- |
| `zM hFelM hMafM hSedM` | the cell's | K9 inversion, exact mirror of `Earth.invert` (same clamps, same fixed-point loop) |
| `ageMyr` | cell age, 500 on continents | `Earth.apply` holds continental age at 500 |
| `fert` | `0.5 + 0.5·(quartile/7)` | `Earth.apply`'s own quartile law, `Params.fertLo = 0.5` |
| `damage`, `pot` | **0** | a snapshot has none; the section's deposit engine grows them from `fert` while it runs |
| `vt vp` | `R(ω × p̂)` split on the cut tangent | the pack's Euler poles (rad/Myr, the units the sim integrates) — the motion the sim would run from this pack |
| `bnd pol` | the counterpart's edge law | `relN` against the face normal, `epsHi = 2000 m/Myr`, oceanic by `hFel < 8000`, older oceanic subducts, C–C collides — `js/edges.js` / `PLT.polarity` |
| `wet` | `zM < 0` | the pack's datum is 0, and the section's own datum (the "sea datum" item deliberately left) |
| `host` | `Extract.host` by the `HOSTS` code | `sediment` / `continental` / `thick continental` / `oceanic` |
| `plates` | `{id, n, wx, wy, wz}` | the sim-frame ω (the pack's geo pole negated-and-swizzled the way `Earth.apply` reads it) and the raster cell count per plate |

One measured number worth keeping: the present-day transect reads `max |vt| = 45.18 cm/yr`. That
is not a bake error — it is the genuine NNR-MORVEL56 rigid velocity at the equator (the Martinique
plate's 0.9 rad/Myr rotation has a long lever at that arc). The 100 Ma poles read 1.8–2.2 cm/yr,
the PALEOMAP epoch rates.

`source.level = 0` means *the pack's own raster grid* (the HUD prints `source L0 · 111 km cells`);
a live cut keeps its geodesic level. The raster has no geodesic level, and the `cellKm` field
carries the real resolution.

## 4. The review of the previous commit found four small debts

1. **The `?pack=` harness test wore the real bundle's id.** `experiments/section-pack.js` §F
   injected a synthetic fixture as `SECTION_PACKS['earth-100Ma-gc0']`, the id the plan's example
   URL names. Once the real bundle loads from `columns.html`, it would have overwritten the
   fixture and the check would have compared the Earth's checksum to the fixture's. The fixture
   now wears `fixture-pack`; the real ids belong to the bake.
2. **`smoke.js`'s "every `js/*.js` loads exactly once" would have counted the bundles as page
   modules.** `js/data/` is generated data, not a module: it is carved out of the page-module
   check and gets its own, with the same discipline (every bundle on disk loads exactly once).
   The suite grew 66 → 67 checks.
3. **The refusal message still said `(the bake lands in M4)`.** It now says what to do instead.
4. **The first draft of the walk closed its final run wrongly** (it could overwrite the wrong
   tuple and lose the open run when a crossing happened at the last step), and its fallback
   bisection could end inside the cell. Rewritten with an explicit `s0` per run before it was
   ever run; the no-jump guard is the part that had to be right.

## 6. Deliberately left

- **The live cutter (the counterpart's `js/slice.js` + the Slice UI)** is not written. It is a
  milestone of the counterpart's own plan; the bake is the offline writer of the same format, and
  the reader side of this repository is complete for both.
- **The bake's home is the counterpart's `tools/earth/`.** The copy committed here exists so the
  bundles in `js/data/` are regenerable from this repository alone (pass it the counterpart's
  pack and commit); the format still has exactly one owner, `port/slice-format.js`.
- **Circle-only.** A polyline walk over a static raster and a window (open) bake have no buyer in
  M4; the format already carries both, and the walk is structured so a polyline is an addition,
  not a rewrite.
- The 0.5° raster exists only for the present pack (`earth-05deg.js`); historical epochs are 1°,
  so the bundles are 1° too. A finer historical bake is a one-line `--pack` change, not a new
  writer.
