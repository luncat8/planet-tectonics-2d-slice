# 0.1.7 — Review follow-up: stack removal and the contact audit

Reviewed `dbf272a` against its previous tree `bd0f08b`; the review fixes issues that the
original green gates did not cover. The release's flow-law changes remain, but the original
contact-audit results are superseded by the corrected measurements below.

## Findings and fixes

1. **The event-site audit was false-green.** `Set.prototype.values()` returns an iterator,
   not an indexable array, so `bSites.values()[i]` and `dSites.values()[i]` produced
   `undefined`. All site records collapsed into one key and the surface window received
   `NaN`. Separately, `seen()` compared the run's total `frames` to the prior event instead
   of comparing the current event frame. `contact-audit.js` now materializes site buckets
   with `Array.from`, passes the current frame into the spacing check, and runs two small
   self-checks before the simulation.

2. **Foundering left empty beds in live stacks.** When a delamination amount crossed a full
   basal bed, the old code set `layTh = 0` but kept the slot in `colNL`. That could leave a
   deposit attached to consumed rock and let empty slots affect later layer insertion and
   compaction. `CRU.delaminate` now removes each fully foundered basal bed with
   `COL.removeAt`; that operation invalidates a deposit hosted by the removed bed and
   shifts the indices of surviving hosts. Partial beds stay in place, and every removed
   volume is booked directly to the matching `ledCons` lithology. Four `m2-check` checks
   cover a peel crossing a bed boundary, stack slots, host indices, and ledger volume.

3. **The unit-error magnitude in the original plan was misstated.** A single extra `×1000`
   makes the unclamped metre-valued rate law 1000× too fast, not 10^6×. Delamination had
   an independent cap typo (`over * 500` rather than `over * 0.5`), also 1000× too large;
   together these explain the whole-stack withdrawals without describing them as one
   million-fold rate. `0.1.7-plan.md` and its report now state the factors separately.

4. **Collapse deposit hosts assumed the receiver's surface slot.** `COL.insertVol` places
   felsic material at its stratigraphic rank, beneath a higher-rank cap, but
   `COL.collapseMove` then mapped source deposits to `colNL[to] - 1`. With a sediment cap,
   that attached a moved felsic deposit to sediment rather than the receiving felsic bed.
   The transfer now locates the receiver's actual felsic host after insertion or thickening;
   `m2-check` covers the moved host, the existing felsic host, the cap host and the ledger.
