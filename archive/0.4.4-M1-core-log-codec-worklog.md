## 3. The codec's decisions, and the sentence each one answers

- **Self-contained** (P3, globe §2.1). Own two-lane FNV, domain `pgt-core-log-v2`,
  own UTF-8, own six-digit rule, own key order; no `require`, no `SlicePack` reference.
  Grounded in the globe's worklog §2.3: `SlicePack.fnvText` is not on the pack's export
  list, so a borrowed hash would be a private reach. `port-check.js` B3 asserts the
  fence by stripping comments and refusing `require(`, `SlicePack`, `slice-format`.
- **Canonical body**, in this order: `format, version, pathChecksum, packChecksum,
  arcKm, tMyr, epochMa, lithologySchema, records, checksum`; each record is
  `{sKm, div, hTotM, beds}`, each bed a four-item array. Unknown fields are refused,
  not carried outside the checksum.
- **`section-lith-1`** names the vocabulary the codec owns: lithologies
  `sed/fel/maf/tephra/lava/sill` (index 0..5) and flags `wet/ore/unconf/intr`
  (bits 0..3). The section's `P.LITH`/`P.FLAG` are asserted index-for-index and
  bit-for-bit by the harness, and `P.layerCap (96) <= LAYER_CAP (96)`.
- **The v1 law ported, not redesigned** (P5): `TH_TOL = 1.5`, `AGE_EPS = 1e-9`,
  ascending unique `sKm` inside the cut, positive finite thicknesses, a real
  lithology, four-bit flags, non-empty and capped stacks, the sum rule, the age rule
  with the `intr` exemption on either side of a contact, and the named refusals for
  schema/version/checksum.
- **Seal closes the sum**: `seal` quantises, sets `hTotM` to the sum of the rounded
  beds, stamps the checksum, then runs the receiver's own `validate` — a message this
  refuses never leaves the build. `encode` accepts only a sealed, valid message.
- **Parse is strict and the v1 rule is kept**: text → shape → quantise → checksum
  required (16 hex) → validate. The wire may carry more digits than the six-digit
  rule; the record may not. A checksum taken over off-grid numbers is therefore a
  mismatch and a refusal.
- **Identity is the import decision** (globe §2.2/§2.3): a different `pathChecksum` or
  arc is `foreign` and refused; the same path over a different full pack is `stale`
  (archived only after confirmation); only an exact identity is `current`. The helper
  returns `{status: 'current'|'stale'|'foreign', reason}` so both importers tell the
  three cases apart without re-deriving the rule.
- **No clock, no randomness, no platform read** — asserted by the harness, so the same
  text hashes the same on both sides.

the harness proves that clearing the flag makes the same record refuse.

## 6. M2 — the adoption

The plan's M2 wording put the port module's own section inside `experiments/core-log.js`;
it is a separate harness instead (`experiments/core-log-format.js`), because a shared byte
must be testable without the engine — and because the globe's matching test is a separate
file too. `experiments/core-log.js` keeps the live path and gains only the v2 expectations.

`js/core-log.js` keeps what belongs to the section (the cadence, the divergence
threshold, the sent/emit ledgers, `note`/`reset`, `columnDiv`, and `strataOK` reading
the live typed arrays) and delegates the wire half: `validate`, `parse` and `json` are
the codec's, `build` assembles records and calls `CF.seal`, and the body gains
`lithologySchema`. The old private FNV/quantisation/body code and the
`port/slice-format.js` import are gone; `CLOG`'s surface is now
`FORMAT, VERSION, TH_TOL, DEFAULT_THRESHOLD, validate, json, parse, build, note, reset,
columnDiv, strataOK, lastEmitted`. The section therefore emits `pgt-core-log` v2 — a
v1 log is a foreign version to both sides, which is the agreed "no legacy reader".
