# 0.3.0 P2.2a — is the map wrapped in x? report

**Yes — the particle engine's physics already wraps in x, and it has to.** The Stokes solver
diagonalises x with an FFT, which *is* a periodic boundary condition; walls in x would need a
sine/cosine transform instead. Every other stage follows: deposit/gather, x Laplacian, melt
backtrace, marker moves, the cluster pair walk and the rigid fit (a plate sitting on the seam
is one body). `experiments/pt-wrap.js` proves it: shift the whole state by 97 cells, run,
shift back — markers match the unshifted run to 7e-10 km, plate counts/Nu/ledger identical,
and a plate parked across x = 0 keeps one cluster id.

What was **not** wrapped was the view: the marker stipple vanished on one side of the seam
when panned, the camera centre drifted unbounded, and zoom-out drew the field 3x but the
markers once. Fixed (`render.js`): markers draw at the nearest image, the camera lives in
[0, wrap), zoom-out stops at one period — pan round the planet forever.

Side-effect of wrap worth fixing: the single-mode start (`icMode 4`) made the planet four
exact copies of a 4000 km box until marker jitter broke it (~300 Myr). The shipped start now
puts 60% of the perturbation on seeded wavenumbers 1..12 — cells of different sizes by
150 Myr, and `new planet` (key `n`) draws a genuinely different planet per seed. Plate drift
is still slow (≲1 cm/yr typical): that is the cluster kinematics (P2.2), not the start.

All fixtures green (pt-wrap 18, pt-crust 27, pt-check 18, pt-lid 3, pt-stability 12,
pt-melt 7, pt-eng-conv 5, pt-asymmetry 3, pt-load 5). Worklog:
`archive/0.3.0-p2.2a-wrap-worklog.md`; snapshot `archive/p22-band-300Myr.png`.
