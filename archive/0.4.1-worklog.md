## 2. `port/slice-format.js` — the format as one shared module

The field table (17 per-sample fields, dtypes, units), the six-significant-digit rule, the
two-lane FNV-1a checksum over the header scalars and the buffers, the validation, the JSON
encoder with its typed-array replacer, `decode`, the globe→section edge-code conversion, and
`latLonAt` (the path block, so both sides label the cut from the same data).

Placed in `port/`, not `js/`: `experiments/smoke.js` asserts that `columns.html` loads every
`js/*.js` exactly once, and a shared format is not a page module. `port/` is also the one
directory the manifest lists.

## 3. `experiments/slice-cut.js` — 57 checks

The measurement the plan's numbers come from. Sections: the stand-in cell set, the walk, the
pack, the twelve refusals, the fit into the section's caps, the resample, the path block.

Three bugs the experiment found, which is what it is for:

1. **A lat/lon bucket grid cannot find the neighbours of a point near a pole** — there, points
   far apart in longitude are metres apart on the sphere. Replaced with a spatial hash on the unit
   cube; the neighbour count went from min 0 to 7..13.
2. **`JSON.stringify` of a typed array is an object, not an array**, so a pack serialized at
   three times the size and decoded to empty fields. The encoder now carries a replacer.
3. **The first box filter double-counted** (it consumed the absolute arc of each column centre
   instead of the delta). Rewritten as a cursor over the cell spans; the thickness integral is now
   conserved to double precision at 128, 512 and 1024 columns.

Numbers it produced: **239 B/sample → L5 46 KB, L6 93 KB, L7 189 KB**; cells crossed within 1 %
of the real grid at three densities; per-cell arc inside [0.37, 1.49] × the mean; the cut reads
the same from either end up to a rotation of one; the walk never skips a cell.
