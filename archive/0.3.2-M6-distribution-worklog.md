## Order of work

1. `0.3.2-plan.md` §M6 written first: the distribution with its decision rule (flux ratio a
   seventh on every seed → the thinning is the bound's; varies with the world → the standing is
   open again), the join windows, and the seed-5 pair named as the world the join must answer on.
2. The join instrument in `pt-heat-tail.js`, declared with the M5 repair counters so the wrap
   closes over the live `frame`. The held branch of the `MT.detach` wrapper ages each sample;
   events and `hottest` carry the same age. Observation only.
3. `movedSeen` added to the wrap: the diff's own relocation count against the kernel's `S.moved`.
   That equality is the instrument's proof of coverage — a missed move would show as `movedSeen <
   movedSum`, an over-count as `>`.
4. Neutrality before any cell: `baseline 0 20` → 5534361194548428, `frb 0.25 20 --scope dep` →
   8159759613119221, `frb 0.25 20 --scope solid` → 2818612275077783, the three M5 values. A
   200 Myr smoke (`baseline 0 200`, fingerprint 8583277235412521) was the first cell where the
   repair fires: `movedSeen` 132 = `movedSum` 132, 81 ids, 123 frames. The 20 Myr cells are too
   short to move anything (`movedSum` 0), which is why the smoke exists.
5. The checker M6 section, written against the measured banks. One bug of its own: `\\'` written
   into single-quoted JS strings (double-escaped apostrophes) broke the parse; fixed to `\'`.
   The distribution table then moved to a second pass over the loaded banks, because the first
   version printed rows before their pair was read.
6. The eight cells, one serial batch (fresh process per cell, `HEAT_TAIL_OUT` to the bank, the
   console summary to the `.txt` neighbour):

```sh
HEAT_TAIL_OUT=experiments/logs/0.3.2-M6-base-s5-600.json node experiments/pt-heat-tail.js baseline 0 600 --seed 5 --kyr 50
HEAT_TAIL_OUT=experiments/logs/0.3.2-M6-dep-s5-600.json  node experiments/pt-heat-tail.js frb 0.25 600 --seed 5 --kyr 50 --scope dep
# and the same pair on seeds 1, 3, 7 (base-s1/dep-s1/base-s3/dep-s3/base-s7/dep-s7)
```

   ~3.3 min per control cell, ~4.5 per candidate, all exit 0. The seed-5 pair ran first so the
   join answers M5's own numbers; it reproduces **6191250240167390** and **1808048552219233**
   exactly, which is the instrument's long-cell neutrality.

## Bank hygiene

Eight new banks, eight distinct fingerprints, one bank per world. The seed-5 worlds now carry
three banks each — the M3 untraced cell, the M5 traced cell and the M6 joined cell — justified
the way the M5 pair was: each carries fields no other bank of that world holds (`trace` and
`hottest.id` in M5; `heldJoin`, `movedAgo`, `movedIds`/`movedSeen` here), and the checker reads
all of them. Nothing pruned; the identity map gains no entry.

## Timing

The batch ran serially so the frame times are the cells' own: controls 14.90–15.57 ms/frame,
candidates 21.35–21.80. Both rows sit ~30–35% above their M5 serial readings (11.696 and 15.768)
— a multiplicative shift on both rows that is host drift across sessions, not the join (the M5
trace was priced at 0.004 ms/frame against its own untraced twin; the join is a position diff per
`G.reseed` call plus one lookup per held sample). The probe's own overhead is the stable part:
+6.1 to +6.6 ms over the matched control on every seed. The frame-time gate (< 20 ms) is red for
the candidate on this host and was green for the same cell on the M5 host; the report says both.

that would price it, and it belongs to whichever plan takes the cold face.
