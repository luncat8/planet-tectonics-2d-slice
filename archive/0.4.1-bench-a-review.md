Compared `90091580e39c59d5335eb63ec76d2389f4706d8e` (bench a: "0.4.0-0.9 — Plans: the shell,
the transect exchange, the section, the sync and the merged page", parent `25daf36`) with the

## 2. Verdict by topic

### 2.1 Keep: the current cut spine

The current plan is the right spine for 0.4.1.

- **The format is already a shared module**, checksummed the way the counterpart already
  checksums JSON (`Deposits.round` + two-lane FNV-1a). A second grammar (`SLICE1`) would be a
  second implementation of the sampling rules, which is the failure mode both plans warn about.
  JSON is pasteable, typed-array friendly, and M0 exists.
- **Fixed 512 columns + arc-length box filter** is the right resample. 9009158's
  `clamp(records)` follows the source level, so `w0` (gap floor, flexure `kf ∝ w0²`, collapse)
  changes meaning with every pack. It also inherits the unmeasured cell-count: it quotes L7
  ≈ 717 intervals (circumference ÷ spacing) and current measurement is **811**, which is already
  over `colCap` 768. The estimate would have shipped a broken fit; the resample is what makes L7
  loadable without raising the cap.
- **Two transports, clipboard as the contract.** 9009158 agrees that v1 is copy/paste, and then
  spends 0.7 deciding a live channel by experiment. Current already concluded the live channel is
  a ladder with paste at the bottom. Same answer; current is further along.
- **Mode L is clock-off, not a clamp.** 9009158 fills an open arc by repeating the end columns.
  That invents crust. A window without end boundary conditions does not run.
- **`plate` not `owner`.** Already fixed here; 9009158 still says `plate_1` from `state.plate`,
  which is fine, but it never caught the `owner` collision because it never wrote the shared
  module.
- **Page map.** 160e6d6 made the particle engine the primary entry. 9009158's 0.3.0 edits would
  revert that. They are not applied.

### 2.2 Take: reconstruction honesty (9009158 0.6.0)

The current seeding table says what is copied. It does not say what is *invented*. 9009158 does,
and that is better.

- **Data horizon.** The globe has aggregate thicknesses and no beds, no geotherm below the
  crust, no lithospheric-mantle thickness. Below the Moho the section is a model. Mark it
  (hatch, overlay) and say so on the page. Current already says "3 layers from the cut · beds
  from t0"; the horizon is the same idea, applied vertically.
- **Assumption record.** Every invented quantity is a named counter (`sediment-age`,
  `sub-Moho-thermal`, `plume-default`, `over-collapse`, `short-plate-merge`,
  `discarded-normal-velocity`, …), in the HUD, the capture and the fixture. Current C6 in
  spirit; 9009158 made it a structure.
- **Identity gate.** `SURF.elev` here and `Surface.elevation` there are the same expression
  with the same constants (`zRef -3342`, `thermK 350`, `zRoot 2091`, `ci` 5–20 km, the three
  densities). So `|z - zM| ≤ 1e-3 m` at frame 0 is an **identity**, not a visual tolerance.
  The residual still goes into `zDyn` (current mechanism); failure of the identity is a mapping
  bug, not a modelling choice. Current's gate was "the declared tolerance". Tightened.
- **Quiet start.** An imported state is not a fixed point of the engine. First Myr: no column
  consumed, no boundary-type change; spin-up residual (volume and mean `z` over 100 frames)
  printed and bounded. Current M2 did not say this.
- **Volume / over-collapse.** Thickness × arc is already conserved by the resample. Excess
  above `hCollapse` must not be pushed silently.
- **Self round-trip.** Export a column-engine world through the same codec, import it, require
  the carried fields to match. Validates the mapping without any judgement about the globe.

Absorbed into `0.4.1-plan.md` §4.3.3–§4.3.5, M2, M3.

### 2.3 Take: runtime authority, not only code ownership

Current §1.1 says who owns a *file*. 9009158 §5 says who owns a *quantity while both run*.
Both are needed. The runtime table (map owns kinematics, inventory, sea, potentials; section
owns beds and returns observations only) is now `0.4.0-sync-plan.md` §1.8.

### 2.4 Take in part: missing geology, without revving the pack

9009158's record is richer: mobile load, `trenchDist`, `relN`, `plumeT`, cell id, footprint
area, plume/wave tables. Some of that the section **derives** (trenchDist and relN from the
seeded edges and `vt` — the engine's own K3), some of it v1 simply does not have.

v1 stays frozen (`port/slice-format.js`, 17 fields, M0 done). Reconstruction derives what it
can, counts the rest in the assumption record. Adding `hMob` / cell / `plumeT` is cheap *before*
the cutter exists and is listed as an open decision (§9); it is not a silent format change.

### 2.5 Take in part: the walk

Current `ds = nbrDist / 3` + hill climb is measured: no cell skipped, arcs sum, reads the same
from either end. 9009158's `0.5 × nbrDist` + **bisection to 1 mm** at a cell change is a better
way to *place* `sKm`, on top of a walk that already does not skip. Absorbed as a refinement of
§3.2, not a replacement.

### 2.6 Reject: SLICE1, variable `nCols`, clamp-fill, vendoring, reverting the page map

- **SLICE1.** Inspectable, additive `name:digits`, units in the name. Current already puts
  units in the name (`zM`, `hFelM`, `ageMyr`). Additive unknown fields fight a shared-identical
  module. M0 exists. Not taken.
- **Variable column count.** Breaks the `w0` calibration; loses at L7 against `colCap`. Not
  taken. Current §9.6 stays open only if a fixture shows the L5 stair-step matters.
- **Clamp-fill of an open arc.** Invents crust. Mode L stays clock-off.
- **Vendoring `js/map/` here.** A pinned copy of a 6 k-line engine, its vendor, an update tool,
  and a "no local edit" checksum — in order to get one page. The globe is the larger project
  and it owns the map. Copying it here inverts ownership. Not taken.
- **`index.html` as the column shell.** The particle engine is the primary entry. The column
  page (`columns.html`) is still behind on transport buttons and save/load; that catch-up does
  not get to steal `index.html` back.

### 2.7 Reject as 0.4.1 work, keep as a named prerequisite: the IIFE / globals pass

9009158 F1 is real: both engines leak `var P`, `var S`, `var SIM`, and a page that loads both
silently rewires the first. Current §4.7 already says a single page is a namespacing pass, not
a detail. Wrapping every file now, while 0.3.0-P3 is still being written, is the risk 9009158
itself names. C1 is a prerequisite of *one-page* 0.9, not of the cut. New P3 files should not
add a second global (`0.3.0-p3-plan.md` §6).

### 2.8 Column chrome is still behind

F2/F3 survive the page swap: `columns.html` has no pause/step/reset/new-planet, no seed field,
no save/load, no overlay bus, no capture. 9009158 re-homed those into a 0.4.0 shell. Here they
stay with `0.2.0-plan.md` (kernels) and `0.4.0-sync-plan.md` E1/E3 (capture, checkpoint). They
do not block the cut.

## 3. Two forks that are not closed by "which plan is further along"

### 3.1 Live coupling: C3 only, or C3 + crust reconcile

Current C3: the globe sends plate intervals, `vt`/`vp`, `bnd`/`pol`, sea. The section slaves
K2 and keeps its own crust. After a few tens of Myr the topography is a 1D planet that
*started* from the cut, not a cut of the globe.

9009158 0.7: the globe re-sends thicknesses; the section keeps beds, adds/removes by
lithology, and books `reconciled` vs `diverged`. The picture stays the globe's; the beds stay
the section's. That is what "in sync" looks like, and it matches both plans' runtime
authority (map owns inventory, section owns vertical structure).

A third answer, better than either alone:

- **Live view (0.9):** C3 kinematics **and** C4 thickness-reconcile, geographic join on
  interval midpoints, five ledger lines (`reconciled`, `diverged`, `diverged-at-import`,
  `fresh`, `retired`).
- **Detached run (mode G, already planned):** C3 only, or the section's own solve. The section
  is then its own planet and the HUD stops claiming it is the globe.

C1 re-seed (hard reset) remains a viewer, not a section.

### 3.2 Where 0.9 lives

| option | cost | file:// | who owns the page |
| --- | --- | --- | --- |
| **A. two documents** (current) | a ladder, a handshake | clipboard always; `postMessage`/`localStorage` browser-dependent | each repo its page |
| **B. vendor the globe here** (9009158) | 6 k lines + pin + Earth-pack size decision | works (one document) | this repo, of a thing it does not own |
| **C. column engine as a library on the globe's page** | C1 on `js/*.js` here, `start(host)`, no self-start; a thin adapter there | works (one document, the globe's) | the globe, which already owns the map and the picker |

C is smaller than B and more reliable than A. The picker, the 3D globe and the cut-plane
overlay (9009158 0.9 §3.2 — a real feature, and it does not need vendoring) all live where the
map lives. This repository keeps the section engine. Clipboard remains the standalone path,
which is 0.4.1.

Until C1 lands, A is the product.

## 5. Decisions the owner made

- **Live coupling is C3 + C4** (§3.1, the recommended option). Detached G stays C3 only.
  `zDyn` is re-seeded at each live import and relaxes only when detached.
- **0.9 is the globe's page hosting the column engine as a library** (§3.2 C, the recommended
  option). Vendoring the globe here is rejected. Clipboard remains the 0.4.1 contract.

Locked in `0.4.1-plan.md` §8, `0.9.0-draft-sync.md`, `0.4.0-sync-plan.md` §4.7 / §6.
