# Milestone M5 Report (ages and the observation log): the return path, closed

The section now returns something. `js/core-log.js` is `pgt-core-log` v1 — one record per logged
column (`sKm`, the column's own `diverged` fraction `div`, `hTotM`, beds bottom-up as
`[lith, thM, formedMyr, flags]`), six significant digits, canonical order, mandatory two-lane
FNV checksum — and the same laws are the acceptance rules: thicknesses sum, `formedMyr` never
decreases upward across contacts neither side flags `intr`, lithologies real, thicknesses
positive. A delamination hole (a `layTh = 0` slot the engine keeps for refuelling) is not a bed
and never enters a record; a foreign log that carries one is refused. Build, commit, reset never
move `S.hash()`: the observation stays an observation.

Bed ages are one convention now: **`layAg` is formation time on the section clock; rock age at
the moment of reading is `t − layAg`.** Imports date every bed they write — growth, refresh and
fresh stacks alike — at `max(msg.tMyr, the section clock at the import)`, so an import never
stamps a bed into the past, and the seeded stacks, the grown ones and the rebuilt ones all pass
the §8.5 law in the same run. The `intr` flag means *placed inside the stack*; the law reads
across a contact when either side carries it.

D4 closed the ladder in both directions: on the manual rung an outbound log is **placed** in the
out field (the message says placed vs sent), the auto-log runs at each accepted message with the
clock as floor, and staleness has an exit: the pin counts 240 waiting frames, demotes to
`unsynced` with K2 released, and only an accepted snapshot re-arms.
