entry review (title, cross-links, the page map in `AGENTS.md`) **and** `0.4.0-sync-plan.md`, the
new plan that governs everything this repository exchanges with `planet-geotectonics`.

script. All ten are either fixed here or answered by `0.4.1-plan.md` with a measurement.

## 3. Gaps found

### 3.1 §4.2's premise is off by one engine (fixed)

"A real great circle is 40 030 km, so a pack cannot be 1:1 for both." The column engine's wrap
**is** a great circle: `P.wrap = 2·π·6371e3` m (`js/params.js`), 40 030 km, aspect 13.8 with its
2 900 km of depth. Only the particle engine (16 000 km, `js/pt/params.js`) needs compression.
So option A is not one compromise for both engines — it is **1:1 for the column engine and ×0.4
for the particle engine**, and the plan now says so per engine instead of taking the worse case as
the general one.

### 3.2 `owner` means two things in the two codebases (fixed)

§4.1's field list carries `owner` for "upstream plate id". In `planet-geotectonics`,
`s.owner[cell]` is the **column index owning a cell** (`js/state.js`) — the field the sampler
dereferences for every sample. A shared format in which a name means "plate" on one side and
"column" on the other will be misread on the first edit. Renamed to `plate`.

### 3.3 The pack had no time, no level, no seed, no gap flag (fixed)

A cut is a snapshot of a running world, and §4.1 described a profile. Missing and now added:
`t` and `epochMa` (when the world was, or the reconstruction epoch), `level`/`gridSeed`/`simSeed`
(which world), `cellKm` (what the cut resolves), `alive` (a cut crosses uncovered gaps where
there is no column to sample — without the flag the section invents crust), and `vt`/`vp` (the
velocity along the cut, and the part of the motion the section cannot see).

### 3.4 "checksum" without an algorithm (fixed)

The counterpart already has one: `Deposits.fnvBytes` — two interleaved FNV-1a lanes seeded
`[0x811c9dc5, 0x9747b28c]`, printed by `Deposits.hex` as 16 hex digits — plus `Deposits.round`,
six significant digits, which is what makes its JSON round-trips exact. A second pair of
conventions would mean the two sides disagree about whether a pack is unchanged. The format now
names both and uses both.

### 3.5 Cells crossed is not circumference ÷ cell spacing (measured, 1.2×)

Every count in §4.1/§4.2 was built on that quotient. A line crossing a lattice meets a new cell
every ~0.8 of a cell spacing, not every full one. Measured on the counterpart's own grid at
`d909476` (three great circles per level, `js/geodesics.js`):

| level | cells V | mean `nbrDist` | circumference ÷ spacing | **cells crossed** |
| --- | --- | --- | --- | --- |
| L4 | 2 562 | 481 km | 83 | 99 / 108 / 96 |
| L5 | 10 242 | 241 km | 166 | 195 / 200 / 200 |
| L6 | 40 962 | 120 km | 333 | 389 / 404 / 406 |
| L7 | 163 842 | 60 km | 665 | 777 / 821 / 836 |

The consequence is not cosmetic: the quotient (665) says L7 fits the section's `colCap` of 768,
and the measurement (**811**) says it does not. L5 (198) and L6 (400) fit with room; L7 has to be
resampled onto the section's columns.

### 3.6 The pack's byte budget was a round number (measured)

§5 M4's gate is "the pack is ≤ 64 KB". Measured at 239 B/sample (six significant digits,
columnar JSON, 21 numbers per sample): **L5 46 KB, L6 93 KB, L7 189 KB** — the default level
breaks the gate. The gate should be stated against what a cut replaces, not against a round
number: one 536 KB Earth pack per epoch, from which a cut takes one line. At L6 a cut is 5.7×
smaller than the file it stands in for.

### 3.7 §4.7 says "two documents" but not how they talk on `file://` (fixed)

Both projects are opened as files. `postMessage` between two `file://` documents, `localStorage`
on a null origin and `BroadcastChannel` are all browser-dependent, and the plan needs a channel
that a user can rely on rather than one that works on the machine it was written on. Added as a
ladder: `postMessage` if the handshake answers, `localStorage` if it is shared, **clipboard and
file always** — because the manual path is the one that made 0.4.1 worth doing in the first
place.

### 3.8 One format, two writers (fixed)

M4 names `tools/earth/bake_section.py` as the writer. The request that opened 0.4.1 is a line
drawn on the live map, which is a second writer with a different lifetime (a reproducible bake
versus a snapshot of a running world). Both may exist; neither may own the format. The format is
now one shared-identical module (`port/slice-format.js`) and the writers are two.

### 3.9 `pot` cited the wrong upstream file (fixed)

"The order of `Renderer.ORE`" — the order the catalogue actually snapshots is
`Diag.ORE_FIELDS`/`ORE_NAMES`, consumed by `Deposits.snapshot` (`js/deposits.js`). The renderer
draws that order; it does not own it.

### 3.10 Shared files needed a home directory (fixed)

`port/PORT.json` was planned but the shared files had nowhere to live. They cannot go in `js/`:
`experiments/smoke.js` asserts that `columns.html` loads every `js/*.js` exactly once, and a
format module is not a page module. Shared files now live in `port/`, which is also the one
directory the manifest has to list.
