## M1 follow-up — altitude grid cleanup (2026-09-26)

`js/geom.js` now builds altitude grid levels in increasing world altitude and converts each
level through the same `sy()` map as the raster. The previous sea-level-only step selection
made the asinh-compressed deep half paint many nearly coincident horizontal lines, and the
separate positive/negative loops made the ordering easy to reverse. The step is now selected
from the deepest visible interval with a 24 px minimum, sea level is left to its dedicated
line/label, and labels use explicit altitude signs. `experiments/view-check.js` adds ordering
and minimum-spacing assertions.

## Review follow-up — vertical overlay mapping and M2 plan (2026-09-26)

Reviewed commit `796bf0f` against the actual Node checks. `view-check.js` failed its two new
grid assertions even though the checked-in log/worklog said PASS. The shared `GEO.sy()`
helper used `(u-uB)/duPx`, which reverses canvas y relative to the raster LUT and `yAt()`;
profile, Moho, mesh, grid and sea-level overlays were therefore reflected vertically.
The grid levels are stored in world-altitude order, while the label gap check had assumed
screen-order traversal; after correcting the transform, that would leave only one label.
`GEO.sy()` now maps `uT` to row 0, and labels traverse in screen order. `UI.pos()` also
removes the canvas CSS border before scaling pointer coordinates; pan/zoom direction and
anchor math were sound, but the previous pointer mapping had a small border offset.

The M2 plan now specifies periodic integer mantle harmonics, semi-Lagrangian T advection,
reuse of existing state fields, whole-record stable sorting, mass-preserving width changes,
explicit rift/subduction/collision transfers, queued topology events, and realistic
step-size validation. Design notes were aligned on screen-y convention, periodic modes,
gap thresholds, event order and the 1D transform limitation.

Validation: `node experiments/view-check.js` — ALL PASS (75 checks); `node
