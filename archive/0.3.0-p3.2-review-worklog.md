# 0.3.0 P3.2 review worklog — what the committed P3.2 got wrong, and what changed

Scope: a review of commit `e0aebbc` (P3.2) against plan §4 P3.2, the P3.2 report, and the P3.2
harness, done before P3.3 development. Each finding below was reproduced from a script in
`experiments/` (or, where stated, a diagnostic outside the repo) before it was fixed. Logs are
in `experiments/logs/0.3.0-p3.3-*.txt`.

Gate counts after the review: `pt-p3-melt` 64 (was 52), `pt-wrap` 24 (was 19), `pt-ui` 45
(was 43), new `pt-p3-erupt` 66. Every other harness is unchanged in count and green.

## Findings and fixes

### 1. The composition gate was vacuous

Section 7 closed felsic and water over a shipped run whose parcels carry `cF = cW = 0`, so the
gate was `0 = 0`. Fix: section 7b seeds a band of parcels (y 100–500 km) with `cF 0.15`,
`cW 0.002` and runs 400 frames. Measured: felsic `9.589e5` closes to `1.16e-10` absolute
(round-off on `9.6e5`); water `1.279e4` closes exactly; 393905 parcel-frames of melt in flight
carry felsic; the store holds 28 chambers with felsic `1.69e5` and water `2.25e3`.

### 2. The burst gate was trivial

`chM[0] >= 0` is always true. It is now `chM[0] > 0` with `tx.intrude > 0`, so the store must
actually hold mass after the burst.

### 3. The freeze-back and whole-parcel transitions were uncounted

`melt.js` changed phase in two places with no counter: the whole-parcel melt and the freeze-back
below `meltHold`. Both now count (`tx.whole`, `tx.freeze`) and carry their mass into the melt
book (`thr.whole`, `thr.freeze`), so the book `segregated + whole − freeze = intruded + in flight`
closes in every regime. Section 2 and section 4 gate them on fixtures (one each). The shipped 100 Myr run reports both: **whole-parcel melts 0,
freeze-backs 0**. So the freeze branch has been exercised only by the fixture, never observed
in the shipped run. That is stated, not claimed as a live result.

### 4. `pt-wrap` never moved the chambers and had no store gate

The shifted-twin check translated the markers and the node rows but not `chX`, and it compared
no store state. Fix: `translate` moves `chX`; `save`/`load` carry `tx`, `thr` and the vent
arrays; a chamber/conduit twin section compares record count, site and stock.

Mutant check (translate of `chX` removed from a temporary copy, deleted after the run; the
reproduction is in `experiments/logs/0.3.0-p3.3-pt-wrap-mutant.txt`): three gates fail —
records A 24 vs B 30; every chamber at the folded site, max `d(x)` 23.1 km; stock max relative
error 0.32. So the gate is sensitive to exactly the defect the P3.2 harness missed.

### 5. The reserve comment claimed per-phase enforcement that does not exist

`params.js` said the reserve is "one line per phase that is admitted above it". `pool.js`
enforces only the sum (`partCap`), so a phase may take the whole reserve. The comment now says
so. Per-phase lines are a P3.5 decision and are not enforced here.

### 6. Two runs were merged in one report line, and the seeded run saturates the reserve

`pt-p3-melt` §8 printed the shipped peak (`24948 of 28263`) on the same line as the refusal
count (`12606`), and that count comes from the seeded run 7b. Two runs in one line is a
reporting defect. A diagnostic copy of the harness (outside the repo) wrapped each `PTPOOL`
transaction and attributed the refusals: all of them are `admit` refusals at the pool's own
capacity. In the seeded run the pool reaches `28263 of 28263` on its first burst (t = 0.05 Myr),
defers 12606 splits, and still closes mass, felsic and water exactly. The deferred melt stays in
its host, which is the plan's "defers, never drops".

Consequence for the P3.2 report: "zero refusals over 100 Myr" holds for the shipped composition
only. A wetter felsic seed (`cF 0.15`, `cW 0.002`) takes the whole shared reserve in one frame.
Fix: §8 now prints the shipped and the seeded reserve under their own labels, and the seeded
saturation is stated. It is not gated as a pass, because a tuning change would flip a gate on a
physical outcome. The reserve size is an input to the P3.5 freeze (see "Left for P3.5").

### 7. The shared check helper printed the wrong number under a `rel` label

`experiments/lib.js` `check.near` printed the absolute difference when the tolerance was
relative, under a `rel` label. Pass/fail is unchanged; the printed value now matches its label
in every harness, and all logs were regenerated from the fixed helper.

### 8. The P3.2 report names the wrong harness for P3.3

Report §8 names `experiments/pt-p3-vent.js`. The plan names `experiments/pt-p3-erupt.js`, and
P3.3 uses the plan's name. The frozen P3.2 report is not edited; this entry is the correction.

## Checked and found correct

- `G.cellOf` writes module scratch (`_i0/_fx/_j0/_fy`), and `G.sampleAt` reads it immediately
  after, so the shared scratch is safe for the roof-strength read added in P3.3.
- The symmetric threshold `meltHold` is a fixed point: a parcel does not ping-pong between the
  solid and the melt phase (the P3.2 worklog's claim holds).
- The equilibrium split's children sit on the phase law's manifold: the next equilibrium pass
  books nothing and the latent identity holds across 100 Myr (`identity 4.948e-9` on a stock of
  order `4e7`).
- Enthalpy: the global residual is `-1.11e-16` in the shipped run.

## Left for P3.5 (recorded, not fixed here)

- **Reserve sizing against a wetter seed** (item 6). `resMelt` and `partCap` are measured on the
  shipped composition only; the seeded run saturates them. The freeze needs a case with the
  airborne populations present, as the P3.2 report already says.
- **Per-phase reserve lines** are not enforced (item 5).
- **`S.mug` under-cover nodes** are not reset by `scatterT`, so a roof's strength can be stale
  where no markers sit. Minor; the roof read in P3.3 inherits it.
- **Chamber stock is always fully molten.** Nothing cools a chamber yet, so the crystallised
  intrusion acceptance is gated on a fixture in P3.3 (`pt-p3-erupt` §10), not on a live
  crystallised record.
