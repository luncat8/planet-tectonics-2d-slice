## Disposition

The user selected local needle/prominence detection for R2: a broad elevated belt should pass,
while a sharp pair and a too-narrow belt should fail. The R2 **definition is now explicit and
implemented in both audit harnesses**, but the full acceptance gates remain red. This does not
select or integrate an M2 brake. Production physics and all numeric thresholds remain
unchanged. The pre-decision diagnostics and K5 accounting remain in
`archive/0.1.8-m1-k5-r2-followup-worklog.md`; this entry supersedes that file's open question
about which R2 shape measure to use.

## Selected measurement

For every non-ghost collide pair `i,j=i+1`:

- Let `peak = max(hTot[i], hTot[j])` and `shoulder = max(hTot[i-1], hTot[j+1])`. The
  local-needle ratio is `peak / shoulder`; it must not exceed the existing `P.beltPeak = 1.5`.
- A built sample still uses `peak >= outerFlank + P.beltRoot`. In its six-cell window
  `i-2..i+3`, count cells at least `outerFlank + P.beltRise`, and require the longest
  contiguous run to be at least `P.beltCols = 4` on at least 90% of built samples.
- The prior `peak / outerFlank` ratio and non-contiguous four-of-six count remain in strict
  reports as legacy diagnostics. Neither is an R2 gate now.

`experiments/lib.js::check.r2ShapeAt` supplies this arithmetic to both
`experiments/contact-audit.js` and `experiments/orogen-measure.js`. `js/params.js` only updates
the `beltPeak` comment. `COL.beltAt`, drawing, the force law, and all production parameter
values remain unchanged. Synthetic checks in `experiments/m2-check.js` cover a six-column
plateau (needle ratio 1, run 6), a narrow pair (ratio 2, run 2), and a split four-cell profile
(count 4 but run 2); the legacy outer ratio is also asserted.

While updating the audit, removed its redundant post-run `beltScan()` call: the final frame
was already scanned inside the frame loop, so that call counted it twice. The strict logs
below are after this correction.
