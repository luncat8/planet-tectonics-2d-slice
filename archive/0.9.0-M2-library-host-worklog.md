# 0.9.0 M2 — the library dry-run host

**Implementation status: present; browser acceptance passed 2026-10-19.** Original record: 2026-10-18.
See `0.9.0-M2-browser-acceptance-worklog.md` for the subsequent real-Chromium run and reproducible driver; §4 below records the original environment limitation.

This is the local host rehearsal only. No globe adapter, live-channel integration, or shared
port change is included. `library.html` is a separate page and does not alter the
`index.html`/`particles.html` mirror.

## 1. Host and namespace decision

`library.html` builds the standard controls with `COLUI.build(mount)` and starts the engine
with `COLSIM.start(mount)`. It loads the canonical 32 classic script URLs from
`columns.html` in the same order, including the three existing baked Earth bundles. It has
no build step, module loader, server dependency, or `columns.html` reference.

The page starts directly from a `file://` URL: the mount's `data-start="section"`,
`data-pack="earth-gc0"` and `data-geo="1000"` select the existing section-start path, which
reads the primary pack from `SECTION_PACKS`. These host attributes override ambient URL
options for the mount. The host keeps all logical engine IDs unchanged and puts the mount in
an open ShadowRoot. Its copied engine styling is in that root; the page-owned
light-DOM `canvas#c` stays outside as the collision probe. The engine canvas with the same id
is resolved from the nested host, not from the document.

The scripted dry run pauses the stand-in globe clock through `COLSECTION.applyClock`, makes
one small deterministic step through the built geology slider and `COLSIM.step()`, derives
a `pgt-coupling` message from `earth-100Ma-gc0`, and applies it with `COLCOUPLING.apply(msg)`.
It then triggers the section's normal core-log button and checks the placed JSON using the
shared codec before stopping and restarting the engine.

## 2. Contract correction discovered during review

M1 named `COLCOUPLING.apply(msg)`, but the implementation only exposed the low-level
`apply(state, msg, opts)` used by the engine and harnesses. M2 adds the advertised one-object
host entry: it serializes the supplied object without rewriting its checksum, then routes it
through the active section's existing parser and path guards. The explicit three-argument
form remains unchanged for internal state-explicit calls. `0.9.0-contract.md` now also names
the step, clock, pack-identity and pack-to-message entries used by M2; the namespace harness
reads and checks all 17 named entries.
