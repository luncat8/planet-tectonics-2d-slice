# 0.1.10 evaluation: the narrow crush hold on eight seeds

## Scope

`archive/0.1.9-k5-donor-floor-evaluation-worklog.md` §7 left one decision open: whether
drain-caused next-frame reclassification is worth a fix. Its recommended option was the
narrow variant (option 2), with the instruction to test it on more seeds first. This job
does that test. The variant was not in the repository (its commit `35816d1` is not in this
clone), so it was rebuilt from the §7 description and checked against the logged numbers
before anything else (seed 1 at 100 kyr, the mixed schedule and seeds 2 and 5 reproduce the
logged counts exactly).

## Decision

**The narrow variant is not adopted.** It cuts drain-caused reclassification, but it fails
the acceptance test §7 set (R1, R2 and R5 margins, on more seeds). Engine code is unchanged.
The branch keeps the evidence only.

- Across eight seeds at 50 and 100 kyr/frame, the base passes 11 of 16 strict runs, the
  variant 5 of 16.
- The variant fails six runs the base passes (seeds 1, 3, 4, 6, 7, 8) and fixes none of the
  base's five failures. Those five are all R5 repeats at 100 kyr (seeds 1, 2, 4, 5, 7).
- It fails the checkpoint spin-up gate on the pinned fixture (below), which §7 did not list.

## Method

- Base: `HEAD` (`496ff02`), exported with `git archive`. Variant: the rebuilt narrow hold,
  saved as `experiments/logs/0.1.10-narrow-hold.patch`.
- Seeds 1 to 8, both rates, 5000 frames each: `contact-audit.js 5000 <seed> <kyr> --strict
  --detail` and `k5-reclass-probe.js <seed> <kyr>e3:5000`.
- The variant's suite (`experiments/logs/0.1.10-narrow-suite.txt`) and the table
  (`experiments/logs/0.1.10-hold-table.txt`, from `experiments/k5-hold-table.js`).

The rebuilt variant, as applied to the tree:

- `COL.markCrushHold` runs after the K4 floor solve (and after the freeze on topology-stable
  frames). It flags both columns of each closing C-C pair whose gap is inside the ordinary
  floor.
- `CRU.flowAvail` caps a flagged column's K5 outflow at its felsic above `P.hFlowMin`
  (= `P.hOceanic`). Unflagged columns are unbounded there, so their arithmetic is unchanged.
- Freed slots past `nCol` have their `edgeShort` cleared (the §5 tail fix). Alone, this
  passes every suite check the base passes, so it is not the cause of the failures below.

## Results

Source: `experiments/logs/0.1.10-hold-table.txt`. Drain and velocity are next-frame
reclassified pairs over 5000 frames.

| totals over 16 runs | base | narrow |
|---|---|---|
| strict verdicts that pass | 11 / 16 | 5 / 16 |
| gate failures | 5 (R5 repeats) | 12 |
| R5 repeats | 7 | 15 |
| drain-caused reclassified pairs | 1006 | 67 |
| velocity-caused reclassified pairs | 272 | 555 |

Drain-caused counts fell in 14 runs, were unchanged in one (5/50, where both are zero), and
rose in one (seed 7 at 100 kyr, 15 to 22, with velocity-caused flips rising from 3 to 299).

Runs where the variant fails a gate the base passes:

| seed, kyr | variant failure | base |
|---|---|---|
| 1, 50 | R3 ceiling 82.5 km (limit 81.75) | 81.3 km, pass |
| 3, 100 | R5 repeat 1 | 0, pass |
| 4, 50 | R2 needle 1.56 and R2 width 88.4% | 1.36 and 92.1%, pass |
| 6, 100 | R5 repeat 1 | 0, pass |
| 7, 50 | R3 ceiling 82.0 km | 81.7 km, pass |
| 8, 50 | R2 needle 1.60 | 1.31, pass |

Other checks on the variant:

- **The 3000-frame legs of §4 of the 0.1.9 evaluation were too short.** The 0.1.9 table
  read the narrow variant as clean on seed 1 at 50 kyr. Run to 5000 frames, the same
  seed fails R3 (82.5 km) and has 232 base drain events against 1 for the variant.
  Those drain counts were never visible at 3000 frames.
- **Checkpoint spin-up gate** (`experiments/checkpoint.js`, 52 checks): base passes with
  the imported run at 6.58e-2 against 6.57e-2 for the fresh section (bound 1e-3). The
  variant gives 6.91e-2 against 6.57e-2 and fails
  (`experiments/logs/0.1.10-narrow-suite.txt`). The fresh run is identical in both trees,
  so the variant moves only the imported trajectory.
- The rest of the suite passes on the variant (`ledger-check`, `coupling`,
  `coupling-link`, `core-log`, `section-pack`, `section-seed`, `slice-cut`, `smoke`,
  `view-check`, `pt-ui`, `port-check`, `deposits`, `m3-check` 22, `m2-check` 324, `r4-check`
  8). Only `checkpoint` fails.
- The worst tallest column at the R3 breaches (seeds 1 and 7, 50 kyr, 5000 frames, from a
  scratch script not kept) is not a held column in either run. The mechanism for the R3
  and R2 failures is not isolated, and this job does not claim one.

What the base shows, which bears on option 1:

- Drain-caused reclassification is common in the base at these rates: 232 pairs in
  seed 1 at 50 kyr, 221 in seed 3 at 100 kyr, 208 in seed 4 at 50 kyr.
- It does not predict the base's gate failures. The five base failures (R5 repeats at
  100 kyr, on seeds 1, 2, 4, 5 and 7) have 11 to 24 drain events each. Seed 3 at 100 kyr,
  with 221, passes every gate.

## Reproduce

```
# from the repository root
mkdir -p /tmp/narrow && git archive 496ff02 | tar -x -C /tmp/narrow
patch -p1 -d /tmp/narrow < experiments/logs/0.1.10-narrow-hold.patch
cd /tmp/narrow
node experiments/k5-reclass-probe.js 1 50e3:5000     # 1 drain pair; base 232 (see the table)
for s in 1 2 3 4 5 6 7 8; do for k in 50 100; do
  node experiments/contact-audit.js 5000 $s $k --strict --detail
  node experiments/k5-reclass-probe.js $s ${k}e3:5000
done; done
node experiments/checkpoint.js                           # 1 / 52 fails on the variant
```

The patch is a `git diff` against `496ff02` (`-p1` paths). Base runs use the same commands in
a `git archive 496ff02` export. The table reads the committed logs:
`node experiments/k5-hold-table.js`. Those logs are named
`experiments/logs/0.1.10-{base,narrow}-{contact-audit,k5-reclass-probe}-<seed>-<kyr>.txt`.
The narrow suite is `experiments/logs/0.1.10-narrow-suite.txt`.

## Next step

**Decided by the user: option 1, accept the base.** The base has more drain-caused
reclassification than the 0.1.9 worklog showed, but no gate in the 16 base runs tracks it,
and the open R5 repeats are not touched by any variant tested here. The narrow variant is
closed. The probe and the table stay as the instruments, and the 232-pair case is a known
reclassification, not a gate failure. Options 2 and 3 are left as follows:

1. **Accept the base** (chosen). Nothing to build.
2. **Hysteresis on the closing kind** (option 3). It is a threshold rule with its own gates
   and needs its own plan. Only pursue it if drain-free K5 matters for something other than
   the gates; measure it with `k5-hold-table.js`-style runs over all eight seeds.
3. **Narrow variant anyway.** Not recommended: it fails six runs the base passes, and the
   checkpoint spin-up gate would have to change to accept it.
