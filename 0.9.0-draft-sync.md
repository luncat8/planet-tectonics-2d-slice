# 0.9.0 — Draft: the integrated globe

Reference record of the later half of the request that opened 0.4.1, kept here so a later session
can see what was asked for and in which words. The path to it is `0.4.1-plan.md` §8; the
prerequisite (a cut that can be copied or saved and loaded here) is `0.4.1-plan.md` as a whole.
Runtime authority is `0.4.0-sync-plan.md` §1.8.

## What was asked

> for some later version like 0.9 plan to have integrated globe with working together top view
> simulation and one of cross-section in sync

## What it means, restated

1. **One globe, one section, both alive.** The top-view simulation runs; one cross-section of it
   runs beside it. Not a screenshot, not a bake — two views of one world moving at once.
2. **The globe's page hosts the section.** Both projects define classic-script globals with the
   same names (`0.4.0-sync-plan.md` §4.7), so one page loading both is a namespacing pass: C1 on
   this repository's column engine (`COLP`, `COLS`, `COLSIM.start(host)`), a thin adapter on the
   globe's side. The globe keeps the map, the picker, the 3D view and a cut-plane overlay. This
   repository does not vendor the globe. Until C1 lands, the integration is two documents on the
   §4.7 ladder — clipboard and file always.
3. **\"In sync\" is C3 + C4** (`0.4.1-plan.md` §8.1). The globe sends the plate intervals along
   the cut (velocities, boundary types) *and* the crustal inventory; the section slaves K2 to the
   kinematics, reconciles thicknesses into its beds, and books `reconciled` / `diverged`. The
   section does not drive the globe. What it sends back is an observation log (S2), which the
   globe may display and must not ingest into a kernel. Detach-and-run (mode G) drops C4 and is
   then a 1D planet that started from the cut.
4. **The channel has to work on `file://`.** In-process when the section is a library;
   otherwise `0.4.0-sync-plan.md` §4.7: `postMessage` if the handshake answers, `localStorage`
   if it is shared, **copy/paste and a file always**.

## What has to be true first

- a cut exists and travels (0.4.1 M1–M2);
- the section can seed itself from one (0.4.1 M2);
- the checkpoint and the coupling envelope exist (0.4.0 M5, 0.4.1 M5);
- the shared format is in the manifest on both sides (0.4.0 M0);
- the column engine is one-global-per-file and does not start itself (C1, §8.6 of the cut plan).

## Features that do not depend on C1 having landed

- the line drawn on the globe (and, later, a cut-plane quad strip coloured from the section);
- snap-perpendicular-to-boundary / snap-along-motion, so a cut is not quietly oblique;
- the observation log per crossed cell (beds, ages, flags, epoch), labelled `observed (section)`;
- a paused globe pauses the section's clock label;
- with the coupling absent, the section still runs standalone and says which mode it is in.

## Open questions this draft does not settle

- the coupling cadence N and the import-cost budget that sets it (`0.4.1-plan.md` §9.5);
- whether crust is applied only at the import or interpolated between messages (recommendation:
  at the import);
- what the adapter has to wrap on the globe's side for a paused globe to pause the section
  without a kernel reading the observation table.
