# 0.1.8 — Plan: collision arrest and event-stable orogens

The column engine has a rate-stable crust ceiling, but continent–continent convergence is
not arrested by the current instantaneous belt scan. The brake fades as its measured belt
shrinks, even after the collision has built and redistributed an orogen. This release
chooses and tests a built-orogen measure before it changes the plate force.

The previous engine plans are `0.1.6-plan.md` (§5, the R4 fixture) and `0.1.7-plan.md`
(the metre/Myr flow laws). The corrected contact-audit baseline and review findings are in
`archive/0.1.7-review-followup.md`.

## 0. Conventions

- State uses metres, Myr and m³ per unit depth; the equations name each unit.
- `experiments/r4-check.js` remains the prescribed two-continent negative-control fixture.
  It drives each plate at 15 mm/yr; it does not overwrite the velocity answer.
- `experiments/contact-audit.js --strict` measures the surface event, collision geometry,
  ceiling, topology memory, stratigraphy and finite-state promises. Its site bookkeeping is
  guarded by self-checks; do not replace event identities with counts.
- No build, modules or network dependency; kernel state is fixed-capacity and checkpointed.
  Every changed physical claim has a reproducible experiment.

## 1. Current evidence and problem statement

`PLT.basal` currently scales collision resistance from `COL.beltAt`'s *instantaneous*
`beltW` and `beltFel`. The 0.1.7 flow fix lets the belt form (root 19.6–29.7 km and early
width 251–441 km on R4), but the contact later consumes or redistributes it: the measured
belt contracts to the two-column pair and closing returns to roughly the prescribed drive.
The fixture's verdict remains **R4 NOT MET**; a speed limit is not an acceptable substitute
for a physical brake.

The first review also corrected two test defects. A `Set` iterator is not indexable, and
an event interval is `currentFrame - previousFrame`, not `runFrames - previousFrame`.
Corrected 0.1.7 runs still fail the two R2 geometry checks on every leg; the 100 kyr legs
also expose an R1 event-site displacement and topology repeats. R3's dt-aware ceiling gate
passes all four runs. These results are the starting baseline, not numbers to relax.

## 2. Contracts

1. **R1 — Events stay quiet.** The largest drawn-surface movement within the actual birth or
   death site is no more than `P.evDzK` times the largest movement elsewhere on that same
   frame. The site comes from the event bucket, never from a `NaN` or a proxy index.
2. **R2 — A collision is a belt, not a needle.** Keep the current peak/flank and four-of-six
   width checks as measured gates. If the definition changes, the force law, drawing and
   audit must use the same named measurement; changing the thresholds to green is not a fix.
3. **R3 — The ceiling remains honest.** `maxH <= crustMax + 35 km/Myr × dt` on both frame
   rates; receiver headroom and the foundering ledger remain exact.
4. **R4 — The collision is arrested by its orogen.** In the prescribed 200 Myr fixture, the
   closing speed in the final quarter is at most 75% of the first-quarter mean, the brake-off
   control remains above 90% of its early speed, and the collision remains measurable for
   the whole run. Report the instantaneous belt, the proposed orogen measure and the force
   each frame; do not hide a growing or stale memory behind one final number.
5. **R5 — Events do not flicker.** No same-site birth/death reversal occurs within
   `P.evGap` frames. Measure at 50 and 100 kyr/frame on seeds 1 and 5.
6. **Mass and replay stay deterministic.** The per-lithology ledger closes to the existing
   tolerances, repeated runs hash identically, and save/load resumes the new state bitwise.

R1, R2, R3 and R5 are gates alongside R4, not optional regressions to revisit after the
brake works.

## 3. The model decision (M0): measure before choosing state

Compare two candidates in an experiment before either becomes a kernel constant.

### A. Plateau excess volume

Measure the felsic inventory above `hFelLand0` in a declared, moving collision catchment:

```text
Vex = sum(max(0, hFel[c] - hFelLand0) * colW[c])
```

`Vex` is a section area in m² (equivalently, volume per metre of out-of-plane depth).
The experiment must define the catchment from the same boundary/run geometry on both
sides, show how it follows a moving edge, and measure leakage when two orogens approach.
This candidate is attractive if the crust itself retains enough of the collision history;
it may be derived state rather than a new buffer, but that must be demonstrated rather than
assumed.

### B. Decaying edge memory

Carry a bounded scalar for the collision boundary that records the orogen the edge has
built and relaxes only on a measured geological timescale when that boundary is no longer
building. State the update in units, including its dt-stability, remapping rule when a
column is born/consumed, and behavior when the plate pair or polarity changes. A remembered
belt width is not allowed to keep braking an unrelated successor edge.

### M0 comparison gate

The two candidates run against the same R4 input and brake-off control, with coefficients
fit on one seed and checked on the other. Compare: early/late closing speed, peak and
late crust thickness, current belt width, memory/inventory continuity through the contact,
R1/R2/R3/R5, and cost per frame. Select the least persistent representation that meets
all contracts. If neither does, report why and revise the state variable; do not ship an
unbounded memory or a direct velocity cap.

## 4. Ownership and serialization

The decision in M0 determines the schema delta:

- A derived inventory must specify its finite catchment and have no history-dependent
  hidden cache. If cached for cost, the cache must be reproducible after reset, checkpoint
  load and topology changes.
- A persistent edge value belongs to the edge, not to a plate ID or a raster index that
  can be reassigned. Column remeshing, birth, consumption, wrap and polarity changes need
  explicit transfer/retirement rules, checked against the `COL.fields` gather.
- A new checkpoint array/scalar changes the column checkpoint record table and requires a
  checkpoint version bump plus corrupt/old-version refusal tests. Save/load must preserve
  the memory and the next frame hash.
- The v1 slice-pack fields are frozen in `port/slice-format.js`. If the chosen state must
  cross a globe/section cut or C4 import to reproduce the force, define a versioned format
  change and coordinate the byte-identical `port/` counterpart and its `PORT.json` manifest.
  Do not silently add a field to v1 or invent a second codec. If the memory is local-only,
  state explicitly what a cut/import assumes and ledger that assumption.

## 5. Milestones

### M0 — Candidate measurement

Extend the R4 experiment with the two candidate measurements and a comparable brake hook.
Keep the live engine unchanged. Include the negative control, both seeds, exact command lines,
frame cost and the corrected contact-audit gates. The output chooses A, B, or a measured
reason neither is adequate.

### M1 — State and identity

Write the selected update/mapping rule as a pure measurement first. Test reset, edge motion,
wrap, split, consumption, polarity change, two neighboring collisions and no-edge decay.
If state persists, add its checkpoint/version tests here; if the format must carry it, land
the coordinated codec change before consuming the field in the engine.

### M2 — Brake integration

Use the selected orogen measure in `PLT.basal`; remove the old instantaneous dependence only
where the new measure replaces it. Tune on R4 seed 1, freeze constants, then verify seed 5
and all four strict contact-audit legs. Do not tune `evGap`, `evDzK`, belt thresholds or
`crustMax` to make unrelated red checks disappear.

### M3 — Acceptance and record

Run `r4-check`, all four strict audits, `m2-check`, ledger, checkpoint, coupling/section,
smoke, view and page harnesses. Confirm `index.html` and `particles.html` remain byte-identical.
Record exact results and a next step in `archive/0.1.8-worklog.md`. A real-browser smoke pass
is still required before calling the particle-page UI validated.

## 6. Out of scope

No eruptive kernels or deposits feature work (owned by `0.2.0-plan.md`), no 3D force model,
no absolute convergence-speed clamp, and no one-sided change to the shared slice format.
