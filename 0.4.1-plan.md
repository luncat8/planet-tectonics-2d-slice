# 0.4.1 — Plan: the cut — a line on the globe's map becomes a cross-section

Draw a line on the top view of `planet-geotectonics`, copy or save what is under it, paste or
load it here, and get a cross-section of that line: real thicknesses, real ages, real potentials,
in the section's own depth-resolved beds.

This is the interactive half of `0.4.0-sync-plan.md` §2.8/M4 (the other half is
`tools/earth/bake_section.py`, the offline bake) and the prerequisite for the 0.9 picture
(§8 here, and `0.9.0-draft-sync.md`). The draft is `0.4.1-draft.md`. Reviewed with the previous
commit: `archive/0.4.0-sync-plan-review.md`.

Counterpart: `https://github.com/luncat8/planet-geotectonics`, **main @ d909476 (0.6.1)** — the
commit every upstream field name in this plan was read against.

Everything measured here comes from `experiments/slice-cut.js` (57 checks,
`experiments/logs/0.4.1-slice-cut.txt`), except the cells-crossed table, which was measured on
the counterpart's own grid at the pinned commit and is reproduced to within 1 % by the stand-in
point set the experiment uses.

## 1. What a cut is

A cut is **one sample per cell the line crosses**, in order, each carrying the arc length the line
spends inside that cell. Nothing is interpolated between cells and nothing is resampled on the
globe's side: the section's horizontal resolution is the globe's, which is the entire point of
cutting a running world instead of guessing at one.

Four decisions follow from that, and they are the plan:

1. **The sample is the cell, and the cell's column is the geology.** `cell → owner → column`;
   thicknesses, age, fertility, damage and the six potentials come from the column; elevation,
   wetness and the boundary with the next cell come from the cell. A cell with no column
   (`owner < 0`, an uncovered gap) is a sample with `alive = 0`, and the section shows a gap.
2. **The line is a sequence of surface points, and the walk finds the cells.** For a two-click
   circle that is the great circle through the two points; for a freehand line it is the polyline
   of the drawn surface points. Both are sampled at a third of a cell spacing, and each sample
   resolves to a cell by a nearest-centre hill climb from the previous cell (§3.2).
3. **Arc length, not cell index, is the measure.** Each sample carries the arc it spans; the
   spans tile `[0, arcKm]`. That is what lets the section resample the cut onto its own columns
   without losing mass (§4.3).
4. **A cut is a snapshot, and it says what it is a snapshot of.** World time, epoch, level, both
   seeds, the source commit and the license travel with it; the checksum covers all of it.

## 2. The two transports

Both are required, because the request asks for both and because they fail differently.

| Transport | Shape | When | Size |
| --- | --- | --- | --- |
| **copy / paste** | `Clipboard.writeText(JSON)` on the globe's side; a textarea and a paste handler on this side | the quick cut: draw, copy, paste | 46 KB at L5, 93 KB at L6 — a non-issue for a clipboard; the button prints the size |
| **save / load** | `Blob` + `a[download]` → `slice-<pack>-<epoch>-<n>.json`; a file input on this side | the cut worth keeping, the L7 cut, the one that goes in a checkpoint | up to 189 KB at L7 |

Both carry the same bytes, and both go through `SlicePack.decode`, so neither can be a second
format. `file://` is why: `navigator.clipboard.writeText` is allowed to be rejected without
transient activation, which is exactly why the counterpart's `js/clipboard.js` keeps the
hidden-textarea path, and why the section page reads a **paste event into a textarea** rather than
calling `navigator.clipboard.readText` (which needs a permission a file page will not get).

Not a transport: `localStorage` and `postMessage` between two `file://` documents are
browser-dependent (§8.2). A URL cannot carry a pack (189 KB); it carries the id of a bundled one.

## 3. The globe's side (the cutter)

Everything in this section lives in `planet-geotectonics`. It is written here as a contract, not
as a patch, because it is that repository's code and its own plan owns the details.

### 3.1 The UI

A **Slice** group next to the map controls:

| control | behaviour |
| --- | --- |
| `Slice` toggle | while on, the left pointer draws instead of rotating; right-drag still rotates. Off = the current map behaviour, untouched |
| `Circle` / `Free` | two clicks (start, through) → the great circle; a drag → the polyline of the drawn points |
| `Samples` | the cell walk, drawn as a polyline through the cell centres, so what the user sees is what will be cut |
| readout | `12 400 km · 103 cells · L5 · 46 KB · closes` (or `open`) |
| `Copy slice` | JSON to the clipboard, size in the acknowledgement |
| `Save slice` | the same JSON as a file |
| `Clear` | drop the line |

The line is drawn on the *rotated* map, so a pixel has to become a surface point and not a cell:
`MapView.direction` gives the display-space direction of the pixel, and the view quaternion's
conjugate turns it into the world direction — the same rotation `Renderer.updateViewLookup`
applies when it fills `viewLookup`, with the same screen-flip convention
(`out[(H-1-y)*W + x]`). A line drawn after a drag is then the same line as one drawn before it on
an unrotated map. The pixel → cell path already exists for the probe (`ui.js probeAt`); the
cutter needs the *direction*, because the walk resolves cells itself and it needs a point between
them.

### 3.2 The walk (`js/slice.js`)

```
sample the path at ds = nbrDist / 3 (a third of a cell: a cell cannot be jumped over)
for each sample direction d:
    cell = nearest centre by hill climb from the previous cell (strict improvement, ties to the lower index)
    if cell changed: bisect the last inside step and the first outside step to 1 m of arc, close
        the previous run there, open the new one
close the last run at arcKm; if the line closes and the last cell is the first, merge the two runs
```

The third-of-a-cell step is what makes the walk not skip (measured); the bisection is what places
`sKm` on the actual crossing rather than on the first sample that noticed it. Measured
(`experiments/slice-cut.js` §B, three densities): no cell is ever jumped (consecutive cells are
always neighbours, all the way round), the per-cell arcs sum to the circumference exactly, the
arc spent per cell stays inside [0.37, 1.49] × the mean, the walk reads the same from either end
(up to where the cut is opened), and the same line yields the same cells twice.

### 3.3 What each sample carries

| field | from | note |
| --- | --- | --- |
| `sKm` | the walk | the arc where the sample's span begins |
| `zM` | `s.z[cell]` | includes `zDyn` (upstream `z = −3342 + felsic/6 + … + zDyn`), so it is the surface as drawn |
| `hFelM hMafM hSedM` | `s.hFel/hMaf/hSed[owner]` | metres, upstream units, copied |
| `ageMyr fert damage` | `s.age/fert/damage[owner]` | copied |
| `host` | `Deposits.HOSTS.indexOf(Extract.host(s, cell))` | the code, not the string |
| `plate` | `s.plate[owner]` | renamed from `owner` — upstream, `owner` is the column of a cell |
| `bnd pol` | `s.edgeType[e]`, `s.polarity[e]` for the edge to the next cell | through `SlicePack.edgeCode`: convergent + polarity 2 → collide, convergent → subduct, divergent → open, transform → neutral |
| `alive` | `owner >= 0` | 0 in a gap |
| `wet` | `s.wet[cell]` | |
| `vt vp` | `s.vel[cell*3..]` split on the path tangent | along the cut, and the out-of-plane magnitude |
| `pot` | the six `o*` fields | order of `Diag.ORE_FIELDS` |

The header adds `source` (repo, commit, the Earth pack if any, epoch, rotation model, `tMyr`,
`level`, `gridSeed`, `simSeed`, `built`), `path` (kind, `lat0 lon0 az0` or `verts`, `closes`,
`arcKm`, `cellKm`), `planet`, `sea` (the solved display level and its mode), `plates`
(`{id, n, wx, wy, wz}` — the pole is useless to a 1D section but free, and it is what lets the
globe recognise the plates in a returned summary), `checksum` and `license`.

#### 3.3.1 What v1 does not carry

The 17 per-sample fields are frozen in `port/slice-format.js`. Reconstruction still wants some
quantities the globe has and the pack does not; it derives them or it counts them as assumptions
(§4.3.3), it does not invent a second field table.

| missing | reconstruction does |
| --- | --- |
| `trenchDist` | derived: `PLT.trench` on the seeded edges, after the plates exist. No `classify` pass at seed time — the cut's own `bnd` types are the state, and `classify` is what checks them on frame 1 (§4.3.4) |
| `relN` | derived from neighbouring `vt` |
| mobile load (`hMob` / felsic / placer) | assumed 0; counted `mobile-absent` |
| `plumeT` and the plume table | the section's own seeded plumes; counted `plume-default` |
| cell index | not needed to seed; a live join keys on arc length and plate runs |
| footprint area | the volume ledger uses thickness × arc, which the resample already conserves |

Adding `hMob` / cell / `plumeT` is cheap before the cutter exists and is listed in §9. After M1
it is a version bump.

## 4. This side (the reader and the reconstruction)

### 4.1 The reader and the mapper (`js/section-pack.js`, `js/section-seed.js`)

Two modules, one page. **`SectionPack`** is the page: the transports, the view, the switches, the
HUD. **`SEED`** is the mapping: `SEED.layout(pack, {seed, t, Tm})` → a state, or a message. It
touches no DOM and no clock, and it takes the two clock values as arguments, because
`columns.html` loads the section modules *before* `sim.js` and a mapping that reached for
`SIM.t` would be reading a module that has not loaded yet. The clock is the page's business
(`reconstruct` sets `SIM.t`, cools the mantle, calls `SEED.layout`, then stops the clocks again).

The reader's one entry point: `SectionPack.load(text)` → `SlicePack.decode` (parse, type,
quantise, validate, verify) → a pack the mapper can use; then `SEED.layout` on it. A rejection is
a message in the panel and nothing else: the shown cut and the shown world stay as they were, and
there is no partial load. The decoder refuses, with a message: a foreign tag, a future version, a
missing license, an edited sample (checksum), a non-increasing `sKm`, a field of the wrong length,
a host code outside the table, a negative thickness, a non-finite number, an unknown boundary
code, a polarity outside −1/0/+1, a path that is neither circle nor polyline, and a last sample
wider than a cell. Thirteen refusals, each a check in `experiments/section-pack.js` §C. The
non-finite one is fed in as an *object*, not as bytes: JSON has no `NaN`, so on the byte path a
non-finite number arrives as `null` and the decoder would legitimately read a zero — which is
also why bundled packs are verified (`SectionPack.loadPack`), not trusted.

`SEED.layout` refuses before it writes a single state field (its `measure` step is pure), so a cut
the section cannot lay needs no restore path. Two refusals: a window longer than the wrap, and a
cut narrower than three columns.

Bundled packs (`js/data/section-*.js`, generated) go through the same function, so `?pack=` and a
pasted blob cannot behave differently.

### 4.2 The page

`?start=section&pack=<id>&seed=&geo=&erupt=`, plus a **Slice** panel on the column page:

| control | behaviour |
| --- | --- |
| `Paste a cut` | a textarea; a paste or the button runs the load |
| `Load a cut file` | a file input |
| `Cut from` | for a bundled pack, the id (also in the URL) |
| `raw cut` / `o` | the strip the paste said, or the section laid from it. The reconstruction is what a load switches to; this switches back |
| `overlay` / `r` | the pack's own `zM` step line, and the hatch below the base of the crust (§4.3.4) |
| `detach and run` | mode G only: start the plate clock on the section's own `t0` (§4.4). A window's copy is disabled, and says why in its title |
| readout | `source L5 · 202 km cells → 512 columns · 78 km · 40 030 km circle · t 120.5 Myr · earth-100Ma · checksum …` and, for a window, `12 400 km window · plate clock off` |

The three switches are `aria-pressed` buttons whose state is read back from `SectionPack` (the
same rule `js/ui.js` follows for the engine bar: one writer, so a button cannot disagree with what
is drawn). `r`/`o` are the section's keys, bound on `window` like the engine's, and both the
section's and the engine's key handlers ignore a keystroke that belongs to a field being typed
into — the paste box is a `<textarea>`, and `m` in a pasted blob must not move the mesh.

The HUD is the section's six lines over the engine's own (`UI.hudText()` is a function of its own
for exactly that). It prints both resolutions — the source's cells and the section's columns —
whenever a load happens, the arc scale whenever it is not 1 (§4.4), the out-of-plane fraction of
the motion along the cut so a boundary that looks quiet is not read as quiet, the assumption record
(§4.3.3) and the ledger (§4.3.5).

A **raw strip** is drawn from the pack *before* any seeding: `zM` as a line, the three thicknesses
as a stacked fill, plate as a colour band, `bnd` ticks, potentials as a heat strip, a lat/lon
ruler from `SlicePack.latLonAt`. This is the "did the paste work" view and it stays as the raw
half of the raw/reconstructed overlay (§4.3.4).

### 4.3 The seeding (what "reconstruct" means)

| section state | from the cut |
| --- | --- |
| `S.nCol`, `colX`, `colW` | the section's own 512 columns (§4.3.1) |
| stacks | three layers per column, bottom-up mafic → felsic → sediment, thicknesses from the cut; ages from `ageMyr` |
| `colAge` | `ageMyr` → the thermal lid, which is how the fan's initial T is seeded |
| `fert`, `oVms…oPla` | verbatim (the whole point — the metallogenic record is the globe's, and the deposits milestone consumes it) |
| `z` and `zDyn` | the section computes its own isostatic surface from the stacks; the difference against the cut's `zM` goes into `zDyn`. `SURF.elev` and the globe's `Surface.elevation` share the same constants, so at frame 0 this is an identity: `\|z − zM\| ≤ 1e-3 m` (§4.3.4). `zDyn` then relaxes to 0 |
| plates | the runs of `plate` along the cut become plate intervals; more runs than `plateCap` 32 → merge the narrowest run into its wider neighbour until it fits, and report the count |
| `colU` | the run-mean of `vt`; the plate solve takes over from the first frame |
| `edge`, `edgePol` | `bnd`, `pol` at the run boundaries, so the section starts with the globe's trenches and ridges instead of classifying them a frame later |
| `edgeRelN`, `edgeAge`, `edgeRPlate` | `edgeRelN` from the neighbouring `colU` (so `PLT.classify` finds nothing to re-sign on the first frame), `edgeRPlate` the right neighbour's plate, `edgeAge` 0 — a seeded boundary has no history, which is what keeps the topology shut for `P.evAge` (§4.3.4) |
| `alive` | a gap sample is not a record: its zero is carried through the box filter, so the columns it covers are *thin* rather than empty, and the surface still passes through them at the `zM` the cut named (§4.3.1) |

The gap row is a measurement, not a preference. Seeding a gap as a trench sliver was tried first,
and a hole at L5 spans ~2.6 full-width columns: the engine retires a sliver by handing its
territory to one neighbour, so one 202 km gap moved 50.7 km of crust across a column and 7.4 km of
relief in a single frame at 10 kyr/f. The box filter's zero is the same information at a section's
resolution, it conserves mass by construction, and it leaves `|z − zM|` an identity for *every*
column instead of an exception for the holes. A sliver record is still used where the section has
no data at all — the columns of an open window outside its arc (§4.4) — and those are safe only
because that mode's clock never runs.

#### 4.3.1 The resample: the section keeps its own column count

The cut is laid on the section's 512 columns with an **arc-length box filter** (§4.2.2 of the sync
plan): a column takes the weighted mean of the samples it covers, each weighted by the arc of the
cut inside it, and a sample partly inside a column contributes that part. Categorical fields take
the sample with the largest coverage. Measured exact to double precision for thicknesses at 128,
512 and 1024 columns (`experiments/slice-cut.js` §E).

Why not one column per crossed cell (L5 198, L6 400)? Because the tuned constants that carry
`w0` — the gap floor, the contact radius, flexure (`kf ∝ w0²`), collapse — are calibrated at 512,
and a section that changes its column count with the source level changes what those constants
mean. The resample keeps one calibration and costs a stair-step at L5, which is what the printed
"202 km cells → 512 columns" is for: measured on the fixture, one column per crossed cell would put
a sample in 198 of 512 columns, leave 314 carrying nothing, and move `w0` from 78 km to 202 km.
`0.4.0-sync-plan.md` §9.6 keeps the other answer open.

#### 4.3.2 What the seeding does not inherit

The globe's columns hold **aggregate** thicknesses; they have no beds. So the starting stack is
three layers and every bed the section shows afterwards was made by the section — the page says so
(`start: 3 layers from the cut, their beds aged from the cut; the section dates its own beds from
t 120.5 Myr`) rather than letting a viewer read the first frame as the globe's stratigraphy. That
is also why a loaded cut starts with the clock off (§4.4): the section it belongs to has not run
yet.

The bed ages are the one place where the engine's own two conventions meet: `makePlanet` writes a
*relative* rock age into `layAg` (decreasing upward), while `js/surface.js` writes the *world time*
of deposition into a new bed, and `js/render.js` prints the number as Myr either way. The cut's
`ageMyr` is a rock age, so the mafic and felsic beds carry it, and a sediment bed — for which the
globe gives no age at all — carries the same value and books `sediment-age`. Keeping the stack
monotone matters more than picking a winner between the two conventions.

#### 4.3.3 The data horizon and the assumption record

The globe's columns end at the base of the crust. Below that the section is a model: the
lithospheric mantle follows the engine's own age law, the fan is half-space cooling plus the
section's plumes, and no imported number is claimed under the floor in the HUD, the probe or the
capture. The horizon is marked by the section page's own overlay (`SectionPack.paint`): the
`zM` step line above, a low-contrast hatch below `z − hDraw`, and one label naming both. It is a
page mark rather than a `js/render.js` feature on purpose — the engine has one renderer, and a
second draw path would be a second thing to keep in sync with the first.

Every invented quantity is a named counter on `S.recon`, read by the HUD, the capture and the
fixture. They are camelCase in code because they are fields of an object literal, not a table:

`sedimentAge`, `subMohoThermal`, `lithosphereDepth`, `plumeDefault`, `mobileAbsent`,
`overCollapse` and `overCollapseVol`, `shortPlateMerge`, `clampedSpan` (always 0: an open window
does not invent crust, §4.4), `discardedNormalVelocity`, `seaDatumDisplay`, `bndCollapsed`,
`bndLost`, `edgeFallback`, `gapColumns`, `outsideCut`, `tailArcKm`, `tailVol`.

`S.recon` is a plain object, so `S.hash()` — which walks the numeric fields and the typed arrays —
does not see it: the state hash of a seeded section is the *crust*, and the assumptions can be
rewritten by an experiment without moving it. `S.reset()` zeroes the record, so a re-layout counts
one world's assumptions and not two.

A mapping version, `SEED.MAP`, is bumped whenever a rule in §4.3 changes, and it travels with the
capture: two reconstructions of one pack are comparable only at the same version.

#### 4.3.4 Identity, quiet start, raw vs reconstructed

Because the two crust engines share the isostasy law, `|z − zM| ≤ 1e-3 m` at frame 0 for every
column is a **hard identity**, not a visual check: `zDyn` is set to the difference the model's own
`SURF.elev` would miss by, and `elev` is nonlinear in thickness, so this is the one place where
the section cannot simply copy the number. Measured `9.1e-13 m` at L5 and at L7 on the fixture
(`experiments/section-seed.js` §A), where the tolerance is against the value the pack carries in
memory and the harness recomputes the box filter itself. A larger error is a mapping bug: it is
refused, not relaxed away.

The imported state is not a fixed point of the engine's dynamics, so the quiet start is stated as
three things the seeding is actually responsible for, all three measured:

- **frame 0, the identity above**, and the view is still: the clock is off, nothing has run;
- **frame 1, nothing is re-signed**: the classifier finds every seeded boundary in the state its
  own `relN` names (0 of 12 changed), and the topology cannot fire at all because a seeded boundary
  has `edgeAge` 0 and `COL.intents` asks for `P.evAge` of history — measured: `nCol` unchanged for
  199 frames at 10 kyr/f, births from frame 300 on;
- **the first frame's motion is the engine's, not the mapping's**: a seeded world moves the surface
  by no more than a freshly reset planet does at the same frame size (measured 2 756 m against a
  control of 3 377 m, both at 10 kyr/f, on the same state the model ships).

The plan first asked for "a few hundred metres" as an absolute bound. It cannot be met by anyone:
the model's own default world moves 3.4 km on its first frame, because a reset planet is not a
fixed point either — `zDyn` relaxes, the fan cools, and a plateau above `hCollapse` starts to flow.
A bound that only the *comparison* can give is what is used, and the HUD prints the comparison:
`spin-up since the cut: crust +… m3/m · mean z … m · N frames · N records of 512`.

After the first Myr the seams are the model's: within it, a fixture cut changed 2 of 12 boundaries,
both to the state the recomputed `edgeRelN` names (one pair the flow brought together, one it
matched in speed) — a section that disagreed with its own classifier would be a mapping bug, and
`§D` of the experiment is exactly that check.

A **raw/reconstructed overlay** draws the pack's `zM` as a faint step line over the section's `z`,
and hatches the span below the base of the crust. At frame 0 the two lines coincide (the identity);
after that they diverge by exactly the section's own evolution, which is the point. The strip is
the same data with the model's marks removed: it is what a load shows *before* `SEED.layout`
answers, and the `raw cut` switch returns to it.

#### 4.3.5 The volume ledger

The resample is conservative, so the ledger is one statement rather than three. Over the whole
cut, `Σ h · arc` of the samples equals `Σ h · Δs` of the seeded columns plus the tail a window left
outside its last column:

```
seeded + tail = cut            measured: 4e-16 relative on the fixture, closed and windowed
```

and the HUD prints that as `ledger: map-equivalent 1.000000 · crust 988692889403 of 988692889403
m3/m`. `mapEquiv` is the ratio form of the same numbers, for a viewer: 1.000000 exactly for a
closed cut (there is no tail), ~0.996 for a window whose tail is booked. It is not a tolerance —
the tolerance is on the closed identity above, and the fixture reads both off `SEED.cutMass` and
`SEED.seedMass` rather than recomputing them, so the ledger the page prints is the one the check
closes.

Two lines beside it:

- **over-collapse** — a column whose total exceeds `P.hCollapse` does not push the excess; the
  count and the volume (`overCollapse`, `overCollapseVol`) are booked here, not absorbed into a
  mantle ledger the section does not own. The collapse kernel spends it if the clock runs;
- **crossings** — `bndCollapsed` (two crossings in one column pair: the faster wins, the loser is
  counted), `bndLost` (a crossing that landed inside one plate after the resample and cannot be
  drawn), `edgeFallback` (a plate seam the cut left without a boundary, called neutral). Measured
  on the fixture: 0 and 0 at L5, 0 and 6 at L7, where 39 runs have to fit 32 plates.

### 4.4 Two run modes

| mode | cut | arc scale | clock |
| --- | --- | --- | --- |
| **G — great circle** | `closes: true`, 40 030 km | **1.00** for the column engine: its wrap *is* a great circle (`P.wrap = 2π·6371e3`) | **allowed, off by default.** The section is a real transect at real scale and it is periodic, so the plate clock can be started and it runs as its own planet; it starts stopped, because the first thing a cut is for is looking at what the globe actually has |
| **L — window** | `closes: false`, e.g. 12 400 km | 1.00 | **off** (`dtGeo = 0`), and it stays off. Real geometry, real beds, real deposits: zoom, probe, drill, prospect — but no tectonic evolution, because a window needs end boundary conditions the engine does not have (option B, `0.4.0-sync-plan.md` §4.2) |

Both modes start stopped and say so: `cut at t 120.5 Myr · plate clock off · the cut as it stands`.
Starting the clock in mode G is one button — **detach and run** — and the HUD stops claiming the
section is the globe from that moment: the label becomes `cut at t 120.5 Myr · running +3.2 Myr`.
Until that button, the section is a view of the cut, not a second planet.

The refusal to run a window is not only the button's `disabled` flag. `SectionPack.frame()` forces
`SIM.dG = 0` whenever `SEED.window` is set, because the slider, the URL and the space bar are three
other writers of the rate and covering them one at a time is how a guard gets missed. A layout
that could not place the cut leaves the page on the strip with the reason (§4.1), which is the
same claim in the other direction: `world` is false, `pack` is not.

A live coupling (M5) is a third mode, **S**: the globe's kinematics **and** its crustal inventory,
with the section keeping its beds (§8.1). Without a coupling the section still runs standalone.

The particle engine takes a great-circle cut at arc scale **0.40** (its wrap is 16 000 km), and
only as a thermal seed: it has no topography and its crust is emergent, so a pack can set its lid
age profile and nothing else. Out of scope here; noted so the plan is not read as promising it.

the same pack checksum.

### M2 — the reconstruction

`SEED.layout` in `js/section-seed.js` + the seeding table (§4.3), the identity and the `zDyn`
residual, the assumption record, the quiet start, the volume ledger, the plate-run merge, the
boundary seeding, the model hatch, the raw/reconstructed overlay, the HUD lines, the three
switches, and the clock-off window mode.

Gate (`experiments/section-seed.js` for the mapping, `experiments/section-pack.js` for the page):
`|z − zM| ≤ 1e-3 m` at frame 0 for every column of every test pack; `seeded + tail = cut` to
1e-9 relative, with both masses read off the mapper's own ledger; over-collapse booked, not
swallowed; the assumption counters equal to what the pack says (`vp > vt` recounted from the
samples, `mobileAbsent` and `subMohoThermal` each one per seeded column) and outside `S.hash()`;
`plateCap` respected with the merges counted; nothing consumed for `P.evAge` and no boundary
re-signed on the first frame; the state reproducible from the pack, the seed and `SEED.MAP`;
a window laid with its tail booked, its outside columns empty, its `dG` pinned to 0 and its run
switch disabled; a refusal that leaves the shown cut and the shown world untouched; the paste and
the file laying the same `S.hash()`.

### M3 — round trip and the catalogue

Save the section's state (the sync plan's E3 checkpoint) and re-load it; the deposit snapshot
(`snapshotSection`) over the seeded section, so the cut carries the globe's potentials into a
catalogue the section can drill. The **self round-trip**: export a column-engine world through
the same codec (the fields the column engine has; the missing ones marked absent), import it,
and require identical per-column thicknesses and ages for the parts a pack carries.

Gate: save/load round-trips bit-identically; the same cut and seed give the same catalogue from a
click, a whole-section scan and a re-import; a body's identity includes the pack checksum; the
self round-trip reproduces the carried fields and a forward run of 1000 frames stays inside the
spin-up bound.

### M4 — the bake and the Earth packs

`tools/earth/bake_section.py` on the globe's side, and `js/data/section-*.js` here, so
`?start=section&pack=earth-100Ma-gc0` opens a real transect.

Gate: the baked profile equals the source pack's cells; the checksum is stable across two bakes;
the license travels; the page prints the epoch and the arc scale.

### M5 — the live link

The §8.2 ladder, the coupling envelope (§8.3), the C3+C4 reconcile (§8.1), the observation log
(§8.5) and the handshake. The protocol is gated **without** a live channel: a pack sequence from
`tools/earth/bake_section.py` (or the cutter) is enough to drive re-sampling, the ledger and the
clock. Turning it live is a transport choice on top.

Gate: the handshake announces its rung, and each rung is testable on its own (a probe that gets
no answer falls through to the next, and the page says which one it is on); a paused globe pauses
the section's clock label; a coupling whose `pathChecksum` is not the section's cut is refused
with a message; with no coupling at all the section still runs standalone; a 20-import sequence
keeps beds on matched columns, books `reconciled`/`diverged`/`fresh`/`retired`, and closes the
mass identity to 1e-9.

## 6. What this version does not do

- no live link (M5), no non-periodic ends (option B), no section → globe *physics* transfer
  (the observation log is display-only, §8.5),
- no bed stratigraphy inherited from the globe — it has none to give (§4.3.2),
- no seeding of the particle engine beyond a note (§4.4),
- no Earth-pack cut until M4: M1–M3 are cuts of synthetic worlds.

## 7. Risks

| Risk | Warning sign | Counter |
| --- | --- | --- |
| the walk skips a cell | consecutive samples are not neighbours | the check in §B, at three densities, on every run |
| the two sides disagree about a field | a pack loads on one side and not the other | one shared format module, checksummed in the manifest |
| a cut silently invents detail | a section feature narrower than the source's cells is discussed as real | both resolutions printed; the resample is conservative, never interpolating |
| the section's isostasy is not the globe's | a seeded profile that does not look like the source | the identity gate (1e-3 m); the residual goes into `zDyn` and is printed |
| an imported state is not a fixed point | a violent first frame, a consumed column, a flipped boundary | the quiet start's three gates (§4.3.4) measured against a fresh reset planet, the spin-up residual on the HUD, and `over-collapse` booked rather than smoothed away |
| the crust kernels are not the units the constants are named in | a seeded plateau loses kilometres of crust in one frame | the two `* 1000` fluxes in `js/crust.js` are deferred with their measurements (`roadmap.md` §3); the section reports what they do instead of hiding it |
| a cut silently invents a geotherm | a probe reading below the Moho quoted as the globe's | the model hatch; the assumption record; no imported number claimed under the floor |
| the cut is presented as the real Earth | a transect figure without a scale | the arc scale, the epoch and the license on the page |
| a plate's motion is perpendicular to the cut | a boundary that reads as quiet | `vp` printed as the out-of-plane fraction |
| clipboard size on a big cut | an L7 paste that feels stuck | the button prints the size; the file path is there for L7 |
| `file://` channels | a live link that works on one browser | the ladder (§8.2), with copy/paste as the rung that always holds; 0.9 is in-process (§8.6) |
| reconciliation looks like mass creation | `diverged` large, or a bed texture that churns every import | the two fractions on the HUD; merge at `layerCap`; cadence from a measured budget |
| geographic join is a heuristic | material moving between columns that are not the same crust | fixture pins both ends of the threshold; the threshold is set by the measured fractions |

## 8. The 0.9 picture

`0.9.0-draft-sync.md` is the request; this is what has to be true for it.

### 8.1 Four couplings, two of them used

| option | meaning | verdict |
| --- | --- | --- |
| **C1 re-seed** | the globe re-bakes the cut every N Myr and the section hard-resets to it | simple and honest, and it throws away every bed the section built. A section that forgets is a viewer |
| **C2 end forcing** | the globe sends end velocities, sea level and trench positions; the section keeps its own state | needs the section's boundaries to sit where the globe's are, which stops being true a few Myr in |
| **C3 kinematic slave** | the globe sends the plate intervals along the cut with their tangential velocities and boundary types; the section slaves its plate solve to them and keeps its own crust | **detached mode G.** Drift of *plates* is bounded because the kinematics are the globe's; the geology is the section's; prescribed kinematics is already a solved problem upstream (`0.4.6-plan-plate-history.md`). Topography will drift, and that is the point of detaching |
| **C4 reconcile** | the globe re-sends thicknesses; the section keeps beds, adds/removes by lithology, and books `reconciled` vs `diverged` | not enough on its own (plates still drift) |

**Live mode S is C3 + C4.** The globe owns kinematics *and* crustal inventory (`0.4.0-sync-plan.md`
§1.8); the section owns beds. K2 takes velocities from the coupling; thicknesses follow the
globe by the table below; K3–K6 still spawn, consume, erode, deposit and grow beds between
messages. When the coupling goes stale (no message for longer than its cadence) the section
returns to its own solve, the banner says `unsynced`, and it is then a detached G.

Join key, geographic first: a new column takes an old column's stack when their interval
midpoints are within `2 × local spacing` on the path (arc length; the pack's own `cellKm` is
the spacing). Plate id is a fast path, not the identity. A small drag of the line keeps most
stacks; a jump rebuilds them. One rule, one code path.

| what changed | rule |
| --- | --- |
| the globe's `hFel`/`hMaf` grew by delta | delta is added as one new bed at the bottom of its lithology, age = globe time since the last import; booked `reconciled` |
| the globe's thickness shrank by delta | material is taken from the top of that lithology downward, the removal is an unconformity on the next bed; booked `reconciled` |
| `hSed` grew / shrank | new top bed, or remove top-down; booked `reconciled` |
| `ageMyr` changed by more than 0.01 Myr | `colAge` follows; the fan is rebuilt at the import, not per column per frame |
| `fert` / potentials changed | potentials follow; existing deposits keep their slots (0.2.0-M3 owns the deposit layer) |
| a new boundary at the column | edge/polarity follow; a new ribbon spawns if the crossing is new; an existing ribbon the globe no longer reports is not deleted (the engine's own dissolution owns that) |
| the section's own kernels changed a thickness between imports | the next import pulls it toward the globe's value; the amount pulled is `diverged`, the residual at the moment of import is `diverged-at-import` |
| no ancestor / no descendant | built fresh from the pack, or retired; booked `fresh` / `retired` |

Every rule ends in a ledger line of `S.recon`. After an import, crust volume equals its value
before, plus reconciled, minus retired, to 1e-9 relative. Two fractions on the HUD and in the
capture — cumulative `reconciled` and cumulative `diverged`, each over the strip's own volume —
are the honest answer to "how much of this section is the globe's planet".

While live, `zDyn` is re-seeded from the identity residual at each import (so the globe's
dynamic topography is not relaxed away). When detached, it relaxes to 0 as in §4.3.

Same-lithology neighbours merge when a column approaches `layerCap`; the merge is counted. A
fixture asserts no column refuses material at the cap in a 20-import sequence.

### 8.2 How the two sides talk

0.4.1's product is two documents and the clipboard: `0.4.0-sync-plan.md` §4.7, the ladder
(`postMessage`, then `localStorage`, then **clipboard and file**), the page saying which rung
it is on. The manual rung is not a fallback; it is the contract, and it is what M1–M2 deliver.

0.9's product is **the globe's page hosting this repository's column engine as a library**
(§8.6). Sync is then a function call, not a channel. The ladder remains the fallback and the
standalone path.

### 8.3 The coupling envelope (`pgt-coupling` v1)

Sent by the globe every N Myr of its own time, over whatever rung is up (or passed in-process
when the section is a library):

```
{ format: 'pgt-coupling', version: 1, pathChecksum, tMyr, epochMa,
  sea: { mode, levelM },
  plates: [{ id, s0Km, s1Km, vt, vp, bnd, pol }],
  crust:  [{ s0Km, s1Km, hFelM, hMafM, hSedM, ageMyr, fert, damage }],
  trenches: [sKm], ledger: { fel, maf, sed } }
```

The section: matches `pathChecksum` to its cut (a different line is refused, not blended),
re-slaves its plates (C3), reconciles thicknesses (C4), follows the clock label and the sea
level. It answers with the observation log (§8.5), which the globe may display and must not
ingest into a kernel.

Cadence: one message per N Myr of globe time, N default 5. The section's own clock may not run
ahead of the last message by more than N; if it would, it waits. An import is atomic: it either
completes (the section is legal afterwards) or is refused with the running section untouched.

### 8.4 Acceptance for 0.9

- the same path, epoch and seed give the same pack checksum and the same section state hash on
  two machines;
- a paused globe pauses the section's clock label;
- with the coupling absent, the section still runs standalone and says which mode it is in;
- a cut whose `pathChecksum` does not match the section's is refused, with a message;
- a 20-import sequence of a pinned world keeps beds on matched columns and closes the mass
  identity;
- the globe's page hosts the section as a library, or the page says it is on the two-document
  fallback and which rung.

### 8.5 The observation log (the return path)

The section returns one thing to the globe: a **core log** for the cells the line crosses. It is
an observation, not a physical field (§1.8 of the sync plan).

- Format: the same JSON discipline as the pack (`pgt-core-log` v1, a field table, a checksum),
  one record per section column: the pack checksum, the column's arc, the bed list (lithology,
  thickness, age, flags), the `diverged` fraction, the section's epoch.
- Cadence: at the sync cadence, and only for columns whose `diverged` fraction changed beyond a
  threshold.
- The globe stores them in a side table keyed by cell, validated before acceptance (thicknesses
  sum, ages monotone). A rejected log is reported and counted; it never enters the globe's
  state. The globe's kernels have no reference to the table; its state hash is unaffected by an
  accepted log — that is the test that keeps the observation on the observation side.
- Shown in the globe's probe labelled `observed (section)`, beside the globe's own modelled
  thicknesses. This is the material the globe's 0.6.1 prospector wants for synthetic core logs.

### 8.6 Where 0.9 lives

The globe's page hosts the section. This repository does not vendor the globe.

Prerequisite, on this side only: **one global per column-engine file**, the name it exports
(`COLP`, `COLS`, `COLSIM`, …); every other top-level name inside an IIFE; `COLSIM.start(host)` /
`stop()` instead of a `document`-guarded bootstrap. The particle engine is not part of this
pass. Until it lands, 0.4.1's two documents and the clipboard are the product.

On the globe's side (its plan, not this one): a thin adapter that constructs the section, passes
each coupling message as a function call, draws the line and a cut-plane quad strip coloured
from the section's palette, and refuses equal or antipodal picks. Snapping the line
perpendicular to the nearest boundary, or along local plate motion, is a display-side
computation of fields the pack already exports.

Nothing local patches a vendored file, because nothing is vendored. A hook the globe's engine
does not offer is an adapter wrap of a public entry point, or a change upstream.

## 9. Decisions experiments must settle

1. Whether the freehand line is resampled to a polyline of drawn points or to a smoothed path
   (a dragged line on a rotated equirect map is not a great circle segment by segment).
2. `ds = nbrDist / 3` against `nbrDist / 2`: the walk is exact at a third (measured) and the
   sample count is what the cost follows. Bisection of the crossing (now in §3.2) is independent
   of that choice.
3. Whether the section may interpolate crust between coupling messages, or only apply at the
   import. Recommendation: apply at the import; interpolating thicknesses invents beds.
4. The plate-run merge rule when a cut crosses more than 32 plate intervals (§4.3) — narrowest
   run into the wider neighbour, measured but not yet loaded into a real cut.
5. The coupling cadence N (§8.3) and the import-cost budget that sets it (`experiments/` once
   M5 has a pack sequence).
6. Settled: live mode S is C3 + C4 (§8.1); detached G is C3 only; `zDyn` is re-seeded at each
   live import and relaxes only when detached.
7. Settled: 0.9 is the globe's page hosting the column engine as a library (§8.6). Clipboard
   remains the 0.4.1 contract. Vendoring the globe here is rejected.
8. Whether `hMob` / cell / `plumeT` join v1 before the cutter is written, or stay assumed
   (§3.3.1). After M1 it is a version bump.
