## 1. What C1 already is (measured by M0, `archive/0.9.0-M0-namespace-worklog.md`)

`0.4.1-plan.md` §8.6 wrote C1 as three clauses. A grep proxy first listed them
(`archive/0.4.4-agreement-worklog.md` §2); M0's harness loads the scripts in a bare VM context
and reads the real global set, and that measurement is the table:

| §8.6 clause | state at `5fae205`, globe pin `3c960e7`, 2026-10-18 |
| --- | --- |
| one global per column-engine file, the name it exports | true for all 25 engine files: `COLP, COLS, COLCOLUMNS, COLSIM, COLGEO, COLRNG, COLSURF, COLPLATES, COLSLAB, COLMANTLE, COLMAGMA, COLERUPT, COLCRUST, COLORE, COLPERF, COLUI, COLRENDER, COLDEPOSITCORE, COLDEPOSITS, COLSEED, COLSECTION, COLCHECKPOINT, COLCOUPLING, COLLINK, COLCORELOG`. Each file adds exactly its own name and is one IIFE ending `else root.COL* = …` behind the guarded `module.exports`, and that guard's CommonJS branch writes no global |
| every other top-level name inside an IIFE | true for the 25: no global lexical name, one object per name. But the engine does not load alone. It reads four non-`COL*` names: `SlicePack` and `CoreLogFormat` (the two shared formats, one load per host page), and `DepositModels`/`DepositEconomics` (the section-local deposit modules in `js/data/`, top-level `var`s under the names they had as port files). With the data bundles it also has `SECTION_PACKS` (ours; no script of the globe's tree names it). `DepositEconomics` is also a global on the globe's page: the recorded collision of M0-D |
| `COLSIM.start(host)` / `stop()` instead of a `document`-guarded bootstrap | true for a document or an element host: `start(host)` resolves host document/window through `hostDocument`/`hostWindow`/`hostElement`, throws `COLSIM.start needs a DOM host and requestAnimationFrame` without one, and nothing starts itself — loading reads no page name, and `columns.html`'s single inline line is the explicit `COLSIM.start(document)`. A **window** host is refused with that same error, because `hostDocument` resolves through `nodeType`/`ownerDocument` only; M1's contract decides whether a window is a host |

So C1 is an **audit-and-contract release**, not a refactor. The engine was already rebuilt
into this shape during the 0.4.x coupling work, and the plans were never updated to say so.
The audit found the one gap no proxy saw: the deposit modules keep un-namespaced names, and the
globe's page defines one of them too. What actually stands between here and "the globe's page can host the section" is: proof
(M0), the control-DOM contract (M1 — `UI.init` reads `.value` off `#sGeo`/`#sErupt` and
queries `#presets button` on entry, so a host must contain the control subtree; today that
markup exists only as static HTML in `columns.html`), and a host that is not
`columns.html` (M2).

## 2. Milestones

### M0 — the C1 audit
`experiments/namespace.js` (node, the house harness shape):

- **A.** load the 25 engine files with the four files they read (`port/slice-format.js`,
  `port/core-log-format.js`, `js/data/deposit-models.js`, `js/data/deposit-economics.js`: the
  page minus its bundles) in a bare VM context. The first three are read at load, so the 25 with
  `port/slice-format.js` alone stop three files. Assert the resulting global set is exactly
  the §1 set, byte-named — no leak, no second spelling;
- **B.** with no DOM in the context, loading starts nothing and throws nothing, and
  `COLSIM.start()` throws its one named error;
- **C.** `start`/`stop` idempotence: two starts with the same host collapse into one frame
  loop, `stop()` stops it, a second `start` after `stop` is a clean restart;
- **D.** the collision half: load the globe's page scripts from a checkout at the pin the same
  way, take its real global set, and assert the intersection with ours is exactly
  `{SlicePack}` — the one name that must collide, because it is the same shared file and the
  host loads it once — plus the collisions recorded in the open. Measured at the pin: one,
  `DepositEconomics`, two different files under one name (our frozen v1 deposit module, their
  v2). It is recorded, re-checked on every run, and carried to M3 as the negotiation input.
  `SECTION_PACKS` stays ours alone (measured: not on their page, and no script or page of their
  tree names it at the pin).

Gate: the harness passes at the pin and re-runs green against a moved globe tip until D says
otherwise — a new globe global that collides is the harness's failure, and that failure is the
negotiation input, not a local rename made silently. The §1 table and the harness numbers go
into the release report, so "C1 landed" is a measured claim with a date and a pin.

### M1 — the host contract (the adapter's API, written down once)
A note in this repository (the release report's contract section), each line already true in
code or made true by exactly one small change:

- **mount**: the host provides a container element; the engine builds its own control subtree
  into it. New: `COLUI.build(host)` writes the standard chrome (the id set M0's harness reads
  off `columns.html` as the authority), `columns.html` keeps its static markup, and one
  assertion pins that the built set equals the page's set — the two spellings cannot drift.
  A host that mounts without chrome (`build` skipped) is not supported: the HUD and sliders
  are the section's own controls, and an adapter that wants them hidden wraps the container
  in CSS, it does not fork the engine.
- **start/stop**: `COLSIM.start(hostElement)` / `COLSIM.stop()`; the canvas the engine paints
  is `#c` inside the host (`hostElement` already falls back from `getElementById` to
  `querySelector`, so a nested container works — that path is what M2 exercises).
- **coupling in**: one call per message, `COUP.apply(msg)`; the handshake-less, in-process
  form §8.2 already names. `COUP.last` is the receipt (matched/fresh/retired/ledger). A
  refused import leaves the section untouched — already gated (`experiments/coupling.js` §C2).
- **observations out**: `CLOG.build(…)` selects at the cadence, `CLOG.json()` is the wire
  text, `CLOG.note(…)` commits after the host accepted it — the commit-on-acceptance rule
  §8.5 already implements, unchanged.
- **mode and staleness**: the section says which mode it is in (standalone, live, unsynced)
  through its existing banner fields; a paused globe pauses the section's clock label by not
  calling, and the staleness demotion is §8.1's waiting-frame rule — no new mechanism.
- **what the host must not do**: read engine internals outside the named entries, ingest an
  observation into its kernels (boundary 3), or vendor either engine.

Gate: every entry named above is exercised from a foreign host by M2's page, so the contract
is consumed, not just written.

### M2 — `library.html`, the dry-run host
One new page, not part of the mirror rule (only `index.html`/`particles.html` mirror), file://
safe, classic scripts, no build: a minimal document that builds the chrome into a nested
container, starts the engine there, loads one of the three Earth bundles through the normal
`SECTION_PACKS` path, and drives a scripted coupling sequence from a second baked pack as if
it were the globe — the in-process rehearsal of everything the globe's adapter will do.
Acceptance: headless-Chromium smoke in the shape of
`archive/particle-page-browser-smoke-2026-10-17.md` — start, pause, step, one coupling apply,
one core-log build/placement, stop, restart; no browser errors; and the engine never touched
`document` directly (M0-B's assertion, repeated in-page).

Gate: the page runs from `file://` with no server and no reference to `columns.html`;
`experiments/smoke.js`'s columns.html-once rule is untouched and still green.

### M3 — the globe-side adapter (their repository)
This plan's deliverable is the request, not the adapter. Handed to the globe with 0.4.4's
answer: the M1 contract, M0's intersection evidence at their pin, and the scope `0.4.1-plan.md`
§8.6 already wrote — a thin adapter that constructs the section, passes each coupling message
as a function call, draws the line and the cut-plane quad strip coloured from the section's
palette, refuses equal or antipodal picks, and treats snapping (perpendicular-to-boundary,
along-motion) as a display-side computation over fields the pack already exports. No hook is
asked of their engine that an adapter wrap of a public entry cannot give; nothing is vendored
in either direction. Their release number and schedule are theirs — their 0.9.0 is climate
integration and its grid audit has begun, so the honest expectation is that this queues on
their ladder, and nothing here presumes otherwise.

### M4 — integration acceptance (0.4.1 §8.4, verbatim)
The six bullets stand as written there: same path/epoch/seed → same checksums and state hash on
two machines; a paused globe pauses the section's clock label; coupling absent → standalone
with a named mode; foreign `pathChecksum` refused with a message; the 20-import identity; the
hosted-library clause with the two-document fallback and its rung named. Live sync stays
C3+C4 and waits for 0.4.4 M3–M5's pair evidence — this release does not open a channel.

## 4. Risks

| risk | warning sign | counter |
| --- | --- | --- |
| the chrome builder and the page's static markup drift | a control works on one and not the other | M1's one assertion: built id set equals the page's id set, read by the same harness that owns M0 |
| a future globe global collides with a `COL*` name | M0-D red at a new tip | the harness is the drift gate; the collision is answered upstream or by a rename with both sides recorded |
| a recorded collision outlives its negotiation | `RECORDED` in `experiments/namespace.js` still names `DepositEconomics` after M3 | each entry is re-measured on every run (still two different files under one name); the rename that resolves it deletes the entry in the same commit, and D is strict again |
| `library.html` becomes a second columns page to maintain | fixes applied to one and not the other | the page owns no engine code and no markup of its own beyond the mount call; chrome is built, not copied |
| the host loads `port/slice-format.js` twice | two `SlicePack` spellings, one page | the contract names it the host's single load; the engine reads `window.SlicePack`, M0 counts one |
| adapter work starts before the pair gates exist | a hosted section whose sync is unevidenced | M3's input includes 0.4.4's state; live sync in the hosted page is M4 and carries §8.4's gates |
| the §1 table goes stale as the engine grows | a new engine file exports a second global or none | M0-A is the exact-set gate; adding a file means adding its name to the expectation, in the open |
