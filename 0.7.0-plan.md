# 0.7.0 — Plan: two views, one clock

0.6 makes an imported section; this release keeps it *synced*. The map stays the authority for
the globe (roadmap §5), the section keeps its own fine structure, and the two are reconciled at
a cadence with every reconciliation delta on a ledger line. The plan is written so that all of
it can be built and gated **without** a live link: a pack sequence exported from a real map run
by `tools/transect-export.js` is enough to drive the protocol, the re-sampling and the fixtures.
Turning that protocol live is a transport choice, and this plan decides it with an experiment
rather than a preference.

Contracts C1..C8 of `roadmap.md` §4 and the ownership table of §5 apply.

## 1. What sync means here

- **The map owns the globe**: plate kinematics, crustal inventory, isostasy, sea level, ore
  potentials, deposit catalogue.
- **The section owns its strip**: bedding, bed ages, the local stratigraphic record, the fine
  thermal structure and whatever the section's own kernels do between imports.
- **A sync is an import with reconciliation**, not an overwrite. The section is never rebuilt
  from scratch unless the line moved or a column has no ancestor.
- **Everything is reported.** Two different things change a column: the map's evolution
  (`reconciled volume`) and the section's own evolution (`diverged volume`). They are separate
  HUD lines and separate fixture assertions, because a viewer must be able to tell which engine
  the section is showing at any moment.

Not in scope: two-way physics. Nothing the section computes enters the map's kernels; the
observation log of 0.9 is display/prospecting data (roadmap §5).

## 2. The transport decision

### 2.1 The options

| option | how | file:// reality | cost |
|--------|-----|-----------------|------|
| A — packs by hand/file | copy/paste or `.slice.txt` per import | works today (0.5/0.6) | a re-import is a user action |
| B — two pages, one channel | `BroadcastChannel`, `localStorage` events, `postMessage` via `window.open`, or an `iframe` of the local map page | unknown until measured; file:// origins are opaque and browsers differ | a channel, a handshake, a fallback, and two live pages to keep in step |
| C — one page, two libraries | the map engine vendored as a pinned library (`js/map/`) beside the column engine, both started by `js/shell.js` | works by construction: it is one document | a pinned copy of a 6 k-line engine and its update process |

### 2.2 The experiment (M0, manual, recorded)

`archive/0.7.0-transport.md` records, for Chrome and Firefox, from `file://` and from a local
`http://` server, on both platforms available to the owner:

- does a second page opened by `window.open` receive `postMessage` from the first (file:// to
  file://), and does the reverse channel work?
- does `BroadcastChannel('sync')` deliver a 100 KB message between two file:// pages?
- does `localStorage` share between two file:// pages, and does the `storage` event fire?
- does an `iframe` of a sibling local file load, and can the parent reach its DOM?
- how long does a 100 KB pack take to cross each working channel, and does the receiving page
  stall while it arrives?

Decision rule, fixed before the results: **use the cheapest channel that works in both browsers
under file://; if only some channels work, use A + C and skip B.** No channel that requires a
flag, a server or a build is acceptable (C7).

### 2.3 Recommendation carried into 0.8/0.9

C. A live link between two `file://` pages is the fragile kind of feature this project has
avoided for its whole history, and the 0.9 target — one page with the globe, the map and the
section — makes the channel unnecessary: with the map engine as a library, sync is a function
call. M0 exists to make that a measured statement instead of an assumption, and to leave a
record if the owner's browsers say otherwise.

## 3. The protocol

One module, `js/sync.js`, DOM-free and node-guarded, used by the page, by the fixtures and (in
0.8/0.9) by the in-page link:

```
	Sync.attach(section, source)      source = { kind: 'packs', next(): pack | null }
	Sync.setCadence(myr)              at least this much map time between imports
	Sync.setLine(line)                the next target line
	Sync.step(mapT, mapPack)          called on the map's event cadence; imports if due
	Sync.report()                     the ledger lines, the lag, the reconciliation fraction
```

Rules:

- The map publishes on its own event cadence (1 Myr by default, the map's `eventCadence`);
  `step` decides whether the cadence or a boundary change on the line makes an import due.
- An import is atomic: it either completes (the section is legal afterwards) or is refused with
  the running section untouched (the codec/legality rule of 0.6 §6).
- The import budget is measured (M4); if an import is more expensive than the budget, the
  cadence stretches so the *average* frame stays inside the budget, and the actual cadence is
  shown in the HUD. A long frame caused by an import is reported, never hidden.
- `Sync` never runs the section's kernel inline in the map's frame beyond the measured budget;
  the budget is a constant in `js/params.js` set by the measurement, as everything else here.

## 4. Re-sampling a running section

### 4.1 The join key

Each column carries its provenance: the pack's cell id and the interval midpoint's latitude and
longitude. On a re-import the join is **geographic first**: a new column takes an old column's
stack when their interval midpoints are within `2 x local spacing` on the sphere (the pack's own
`area_m2` gives the local spacing); the cell id is only a fast path. This makes the same rule
work for a fixed line whose crust moved under it and for a line the user dragged.

### 4.2 The reconciliation table

For a matched column (the join found an ancestor):

| what changed | rule |
|--------------|------|
| the map's `hFel`/`hMaf` grew by delta | delta is added as one new bed at the bottom of its lithology, age = the map time since the last import; booked to `reconciled` |
| the map's thickness shrank by delta | material is taken from the top of that lithology downward, the removal is flagged as an unconformity on the next bed, and the volume is booked to `reconciled` |
| the map's `hSed` grew | a new top sediment bed, age = the map time since the last import; booked to `reconciled` |
| the map's `hSed` shrank | remove top-down; the missing volume is booked to `reconciled` |
| `age_myr` changed | `colAge` follows the map, and the fan is rebuilt at the next import only if the age changed by more than `0.01 Myr` (the fan is not rebuilt per column per frame) |
| `fert_1`/potentials changed | potentials follow the map; existing deposits keep their slots (0.2.0-M3 owns the deposit layer) |
| the map reports a new boundary at the column | the column's edge/polarity follow the map; a new slab ribbon spawns if the crossing is new; an existing ribbon that the map no longer reports is not deleted (the engine's own dissolution owns that) and the divergence is counted |
| the section's own kernels changed a thickness between imports | the *next* import pulls it back toward the map's value; the amount pulled is booked to `diverged`, and the residual (the section's local deviation at the moment of the import) is booked to `diverged-at-import` |

Two numbers result, both in the HUD and the capture: the cumulative `reconciled` volume and the
cumulative `diverged` volume, each as a fraction of the strip's own volume. They are the honest
answer to "how much of this section is the map's planet".

### 4.3 Unmatched columns

- A new column with no ancestor is built from the pack by the 0.6 kernel, one column at a time,
  and counted as `fresh`.
- An old column with no descendant (the line moved away, or the crust it stood on was consumed)
  is retired: its mass is booked to `retired` and it leaves the grid. Its identity is kept in the
  report for the session so a viewer can see where it went.
- A change of *line* is a special case of the above: the next import's join is geographic, so a
  small drag preserves most stacks and a big jump rebuilds most of them; the fraction is
  reported, and the plan has no separate "line moved" code path (one rule, one code path).

### 4.4 No silent mass (C6)

Every rule above ends in a ledger line of `S.recon`: `reconciled`, `diverged`,
`diverged-at-import`, `fresh`, `retired`. The fixture asserts that the sum of the section's
crust volume after an import equals its value before, plus the reconciled terms, minus the
retired terms, to 1e-9 relative — the same discipline the engines already apply to their own
kernels.

## 5. The clock

- When synced, the map's `t` is the master and the section follows: `stepTo(mapT)` runs the
  section's own validated substeps, never larger than the geological slider's validated range
  (`geoMin..geoMax`), so a catch-up is a sequence of ordinary frames and not a leap.
- The section may not run ahead of the map. Its lag is displayed; a lag above
  `maxLagMyr` (a parameter set by M4's measurement) triggers a bounded catch-up and, if it still
  cannot keep up, the HUD says `behind` and the map's cadence is stretched (the protocol of §3).
- A pause pauses both. A "section only" inspection mode exists (the section's own clock runs
  while the map is paused) and marks the view `unsynced` in the banner, because the section's
  result no longer belongs to the map's epoch.
- Both clocks and the lag are on the HUD's first line, and both appear in the capture (C5).

## 6. The page

The shell of 0.4 already switches views and keeps the inactive engine's world. 0.7 makes the
*inactive* view step: only the visible view renders, both step, and one control bar drives the
pair (the map's transport is the master; the section's own transport is disabled while synced
and shown disabled rather than hidden).

The section view gains:

- the sync banner (epoch, lag, cadence, `reconciled`/`diverged` fractions, sync state);
- the pack history strip: the last few imports as ticks on the map-time axis with their sizes;
- a `Pause and detach` action for inspection, which is exactly the `unsynced` mode of §5.

## 7. Milestones

### M0 — the transport experiment

§2.2, recorded in `archive/0.7.0-transport.md`, with the decision rule of §2.2 and the resulting
choice written down. Gates nothing but the transport choice; the rest of the release does not
depend on it.

### M1 — the protocol and the clock

`js/sync.js`, the clock rules of §5, the HUD lines, the capture fields. Gate
`experiments/sync-clock.js`: monotone time, never ahead, the lag bound enforced, a paused map
pauses the section, and `unsynced` mode is reported.

### M2 — re-sampling

§4, including the geographic join, the reconciliation table and the `S.recon` ledger lines. Gate
`experiments/sync-recon.js` on a sequence of synthetic packs: matched columns keep their beds,
unmatched columns are fresh/retired, the mass identity of §4.4 holds at 1e-9, the legality audit
passes after every import, and the accumulated fractions match the recorded values.

### M3 — a real pack sequence

`tools/transect-export.js` gains `--sequence <world0.pgt, world1.pgt, ...>` (or a single world
stepped between exports, `--step 1 --count 20`), so a real 20 Myr history of one line becomes 20
packs plus the map's own plate/boundary history. Gate: the sequence imports in order, the
reconciliation fractions are recorded, and the section's own clock tracks the map's epoch within
its lag bound.

### M4 — cost and cadence

`experiments/sync-cost.js` measures the import cost at 180/717/2048 records and with stacks
averaging 4/12/30 beds, the cost of the fan rebuild, and the reconciliation's bed-split cost;
the measured numbers set the import budget and the default cadence in `js/params.js`.

### M5 — acceptance

A recorded 1000-frame run with `--sequence`, at 10 and 100 kyr/frame: no NaN, no capacity
refusal, the ledgers closing, the reconciliation fractions reported, the import budget respected
on average, and the fps measured on a real machine (`run` note in `archive/0.7.0-worklog.md`).

## 9. Acceptance

1. With a pack sequence from a real map run, the section tracks the map's epoch for 1000 frames,
   reports its lag, and never runs ahead.
2. A column keeps its beds across imports when its geographic ancestor is found; when it is not,
   the rebuild is counted as `fresh` and the old material as `retired`, with the mass identity
   holding at 1e-9.
3. The reconciliation and divergence fractions are reported and are stable run to run for the
   same sequence and seed.
4. An import cannot leave an illegal or partially written state: a refused import leaves the
   running section untouched with the reason in the panel.
5. The average frame stays inside the measured budget with imports at the shipped cadence, and
   the page reports any single long frame caused by an import.
6. The transport choice is recorded with its evidence, and nothing in the release depends on a
   channel that the rig could not demonstrate.

## 10. Risks

- **Reconciliation can look like mass creation.** It cannot be avoided — the map and the section
  are different models of the same material — so the plan's answer is the ledger and the two
  fractions, not a pretence of exactness. If the fractions are large in a typical run, the
  cadence is too long or the section's own kernels drifted, and the number says which.
- **The geographic join is a heuristic.** A weak threshold moves material between columns that
  are not the same crust; a tight one retires more than necessary. M2's fixture pins both ends
  and the threshold is set by the measured fractions, not by feel.
- **Bed texture under repeated reconciliation.** Beds split on every import and the layer cap
  (96) is a hard limit. The reconciliation merges same-lithology neighbours when the cap is
  approached, and the merge is counted; a fixture asserts no column refuses material at the cap
  in a 20-import sequence.
- **Two live engines cost twice.** Only one renders, but both step; the budget measurement covers
  the pair's combined frame and the page reports each engine's ms separately (0.4's HUD order).
